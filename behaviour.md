# AU19 #853: what the timing scripts do

I read the source and didn't run any of it. Sources: `phos.TimingAssistant.moon` 2.0.2, `phos.snap.lua` 1.0.3, `petzku.Snapper.moon` 1.0.1, `ua.ShiftCut.lua` 3.1, `ua.JoinSplitSnap.lua` 1.2, `0x.JoinPrevious.lua` 1.

Terms: *kf* is a keyframe number. `f(t)` is `frame_from_ms(t)`, the frame shown at time t. `ms(n)` is `ms_from_frame(n)`, the start time of frame n. Writing `ms(f(t))` rounds t to the start of its frame.

|---|---|---|---|---|

| **phos.snap: Snap start** | For each selected Line: the start goes to the last kf before `f(start)`. If the start is already on a kf and the next kf is before `f(end)`, it goes to that next kf instead. Pressing again moves it the other way. | `ms(kf)` | With no kf before the start, `ms(nil)` throws. | When the start is on the last kf, comparing `keyframes[k+1]` (nil) throws. |

Failing that, if the previous **non-comment** Line ends within 620 ms and not on a kf, it **links**: start = exact − 120 ms and previous end = start − gap (0). ## What HikariSub already has

- `GLOBAL_SNAP_WITH_START`/`_END` (5158/5159, "Change start/end time to nearest keyframe", Shift-Left/Right) snaps the active Line's start or end to the **nearest** kf (or a shown Line's boundary) within 5 s, staying before the end (or after the start). It has no direction.
- `GLOBAL_JOIN_WITH_PREVIOUS`/`_NEXT` (5152/5153, "Merge with previous/next line", F4/F5) **merges text**: it joins with `\N`, keeps all tags, and spans both times.
- `GLOBAL_JOIN_PREVIOUS_AUDIO_SELECTION` (5216, FA17): the active Line takes the audio selection, and the previous Line's end becomes its start. It needs audio.
- `GRID_MAKE_CONTINOUS_PREVIOUS_LINE`/`_NEXT_LINE` (4551/4552): each selected Line's start goes to the previous Line's end (or its end to the next Line's start). The neighbour doesn't move.
- `GRID_SPLIT_BY_VIDEO_TIME` (4521): splits at the video frame.
- `AUDIO_LEAD_IN`/`_OUT` (1026/1027, C/V in the audio box): the active Line's audio selection, by `audio.leadInValue`/`leadOutValue` (200/300 ms), without rounding or an overlap check.
- `GLOBAL_SHIFT_FRAMES_TO_VIDEO_*` (5217–5220): ShiftCut's "by end" (the same `+1`). Shift times (5030/5300) covers the ms/frame whole-Line shift.
- The Timing postprocessor (5214/5215): lead-in, lead-out, close gaps and keyframe snap on many Lines. This is the batch form of JSS Snap and ShiftCut Link/Snap.
