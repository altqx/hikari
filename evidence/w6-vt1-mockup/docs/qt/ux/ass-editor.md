# ASS editor

The [mapped editable prototype](https://github.com/altqx/hikari/blob/616d2f0bfb0bfe28f0dcd792c043e7034ee1606e/HikariSub/prototypes/ass-editor-mapped/README.md) received [altqx's “lgtm”](https://github.com/altqx/hikari/issues/28#issuecomment-5853343345) on 2026-09-27. This accepts the implementation approach: native Qt Quick text input with Hikari's ASS highlighting/spelling and an editable hidden-tag projection, with Raw ASS authoritative. Enter commits and advances outside active IME composition; candidate confirmation remains with the input method. A read-only clean preview alone does not meet the requirement.

The hidden view maps UTF-16/grapheme spans to source offsets, retains untouched ASS tokens, and preserves attempted text when an ambiguous operation needs Raw recovery. Drawing and malformed spans need explicit handling without a silent capability loss. Production grammar, Style-aware restoration and history integration must extend the representative prototype rather than adopt its fixture guards as permanent feature limits.

**Boundary defaults, accepted by altqx on 2026-09-29:** with tags hidden, text typed at a hidden-tag boundary is inserted **after** the boundary tags, so it takes the formatting that follows the caret. A hidden-view replacement whose selection spans hidden tags **retains the exact intervening tokens** and replaces only the visible text. It never silently deletes those tokens and never refuses the edit. Before-tag insertion and refusing cross-tag replacement remain reviewed alternatives, not defaults. Whether either alternative ships as a user preference is not decided here. The draft/transaction contract (when an editor draft becomes a Document command, how it groups for Undo) belongs to [Define edit drafts, commands and undo transactions](https://github.com/altqx/hikari/issues/43), not to this editor contract.

Bounded evidence comprises 26 mapping fixtures and 11 native offscreen observations, including synthetic input-method events. That evidence answers the design question: a native Qt Quick text input can host the mapped hidden-tag projection without fighting Qt's input-method path. On 2026-09-29 altqx closed the [native editor ticket](https://github.com/altqx/hikari/issues/28) on that basis. The remaining obligations **transfer by name** to the [implementation sequence](../proposals/implementation-sequence.md) as required evidence. They are not recorded as passes: **E28-ime** actual OS IME/candidate behavior on Windows and Linux; **E28-rtl** RTL/bidi editing and shaping; **E28-at** UIA/AT-SPI and NVDA/Orca observations of the editor; **E28-grammar** complete ASS grammar including drawing, malformed and Style-aware restoration cases; **E28-undo** production undo grouping under the accepted transaction policy; **E28-shortcuts** complete editor shortcut coverage; **E28-perf** calibrated editing performance. A failure in any of them reopens this contract through a new decision ticket; it does not narrow the capability.

The surrounding controls use the accepted **local inspector** in the [reviewed surface layouts](reviewed-surface-layouts.md), within the familiar right-hand Editor panel. This does not replace the Classic shell with a global inspector or change the accepted stacked Original/Translated fields.
