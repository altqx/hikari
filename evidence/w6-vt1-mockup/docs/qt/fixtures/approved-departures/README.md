# Initial compatibility specimens

These original synthetic inputs make the six [approved departures](../../compatibility-decisions.md) concrete. They are specification data, not a rewrite parser, test suite, executed legacy oracle or complete corpus. The [manifest](manifest.json) records input bytes/hashes, provenance, steps, comparison rules, accepted expectations and separate **not-executed / not-implemented** runtime statuses. No expected complete serializer output has been invented.

Run `python prepare-fixtures.py` from this directory to regenerate only these known synthetic files and the manifest. It does not launch HikariSub, load a decoder/font, read credentials, alter user data or access the network. Git attributes preserve exact input bytes, including the deliberate UTF-8 BOM, CRLF, trailing spaces and repeated unknown sections. The embedded font-like payload is deliberately opaque and invalid: this tests retention, not font parsing or renderer output.

The Session files are **templates for a disposable fixture harness**, not portable Sessions to open in the user's current application profile. They refer to named synthetic placeholders; audio is not supplied. A native harness must bind controlled resources and temporary absolute paths, capture each derived input's hash, isolate the profile and restore each scenario independently. The legacy restore path destroys/replaces open tabs and writes Session/options state, so reading these files is not authorization to load them into a live user Session. No such runtime action has occurred.

For a characterization run, record executable/dependency hashes, OS/toolchain, exact invocation or interaction trace, input and scratch-output hashes, observed semantic/byte results, errors and timestamps. Preserve the old observation even when it differs from an approved outcome. Source-predicted behavior stays distinct from a reproduced result. For the rewritten implementation, use its public boundaries and the accepted test stack; a manifest/hash check alone cannot qualify any behavior.

Coverage is intentionally small: unknown/repeated ASS content, explicit conversion loss acceptance/staleness, omitted versus explicit Session Audio, equal-time comparisons, two independent rational MicroDVD rates, signed VFR frame-index differences, an empty/nonempty TLMode pair and ordinary format precision. The complete accepted contracts still require encoding/undecodable bytes, invalid/negative/overflow timing, malformed TLMode/marker precedence, media association provenance, full conversion losses, actual legacy versions, supported platforms and larger representative corpora. Absent cases are missing evidence, not removed requirements.
