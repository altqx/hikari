# Settings and action migration worksheet

**Proposal, not an accepted schema or implementation.** Companion to [Design settings, shortcuts and the one-shot importer](https://github.com/altqx/hikari/issues/44) and [Prototype settings, shortcuts and migration review](https://github.com/altqx/hikari/issues/52). This turns the source inventory into an enumerated destination worksheet. Hikari owns the Qt layer; the destination names below are responsibility descriptions, not promised API or storage paths.

The accepted exclusion is legacy themes. Accepted editable hidden ASS, Enter committing and advancing outside IME, Classic shell, shared Workspace, optional Home, follow-editing tools with optional pin, and protected comparison remain constraints. Import policy, shortcut precedence and C04 are still proposals. Per-user storage with explicit portable mode is already settled.

| [Routing exceptions](settings-migration-map/routing-exceptions.csv) | 13 rules/families | Fixed handlers, cross-context routes, dynamic macros, blank records and C04 |
| [Other resources](settings-migration-map/resources.csv) | 10 resource families | Settings versus authored collections, direct readers and excluded theme files |
| [Verification record](settings-migration-map/verification.json) | Counts, source hashes and checks | Auditable limits, not a runtime pass report |

`map-proposed` means an explicit candidate destination exists; it does **not** mean a parser, transformed value or compatibility fixture has passed. `preserve-unresolved` retains the original token pending the stated interpretation/capability question. `exclude-accepted-theme` is the only intentional exclusion. An unknown key or value encountered in a user's actual files must produce an additional unresolved record; the 207 rows are the declared source registry, not a claim that every historical/private key is known.

The count excludes reserved enum zero, dynamically registered macros and internal control-handler IDs. All 71 explicit option-default assignments agree with the inventory; the remaining keys have no explicit assignment, which must not be conflated with an explicit empty, false or zero. There are 86 explicit default shortcut bindings and 226 entries in the separate naming table; labels missing there are identified in the worksheet. A missing default is not proof that an operation is unsupported or deliberately unbound.

## Proposed ownership and value boundaries

Most preferences belong to an Application profile. The audio, editor, Grid, timing, conversion, Search, Styles and automation subdivisions identify their consumers. They initialize behavior or a view; they do not import selected Lines, create an edit, run an operation, start playback or alter authored content. Shared Workspace owns candidate window/panel restoration data. Tag buttons, rules, dictionaries and catalogs are authored collections with ordering and original records retained.

Script-property template text and its enable flags are not a Document's Script properties. Conversion Style/catalog names remain references to actual catalog records. Original/Translated visibility defaults do not replace a Document's translation-mode content/serialization flag. Session resource associations and recovered Documents use their dedicated readers; no old autosave index is invented. [Data inventory](https://github.com/altqx/hikari/blob/1eea34cd5db8db276f2e71cdff3f43f345cefd5b/docs/research/data-inventory.md)

Keep legacy decoding and modern typed interpretation separate. The old store is a string array: booleans compare exactly with `true`, integers use `wxAtoi`, floats return zero when parsing fails, coordinates split on a comma, and brace tables strip wrappers/indentation. The importer needs the raw token and a parse diagnostic rather than only the getter's lossy result. The audio-file boundary is ordinal through `AUDIO_WHEEL_DEFAULT_TO_ZOOM`, not every key starting with AUDIO. [Getters](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/config.cpp#L155), [table grammar](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/config.cpp#L732), [partition](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/config.h#L451).

Concrete nontrivial mappings:

- **Time and counters:** AUDIO_DELAY is milliseconds before sample conversion; audio volume/zoom tokens are control positions, not interchangeable linear gains. SHIFT_TIMES_TIME and SHIFT_TIMES_DISPLAY_FRAMES retain separate millisecond and frame shift offsets; SHIFT_TIMES_OPTIONS bit16 selects the displayed mode. Preserve both offsets under the accepted typed-time contract. Decimal conversion FPS is retained without silently inventing an exact rational. GRID_SAVE_AFTER_CHARACTER_COUNT submits editor typing changes to the Document; it is not a disk-autosave interval. [Offset storage](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/ShiftTimes.cpp#L212), [typing submission](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/EditBox.cpp#L1562).
- **Packed choices:** retain all bits, including unknown ones, in find/select/column/filter/comparison/postprocessor masks. Keep copy and paste column masks separate. Tag buttons retain all 20 slots with tag, insertion mode and name, including currently hidden slots. Timing profiles are positional strings: the writer repeats `MoveToVideoTime` for the audio field, so a label-keyed parser would lose information. [Tag slots](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/EditBox.cpp#L1794), [profile writer/reader](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/ShiftTimes.cpp#L800).
- **Unavailable or unexplained preferences:** keep FFMS2 seek mode, GPU-conversion request and VSFilter instance as capability requests until adapter equivalence is established. Two audio flags have preferences/default evidence but no direct runtime getter found. Two old shift booleans coexist with the live packed flags. DONT_SHOW_CRASH_INFO has registry evidence without a direct consumer. None is silently deleted.
- **Appearance:** PROGRAM_THEME, 139 theme colors and theme files are excluded. PROGRAM_FONT, Grid/editor font sizes, ASS colors and color-picker history remain in scope. Raw geometry requires screen/DPI reconciliation with the accepted Qt layout; it is not directly replayable docking state.

## Actions, contexts and fixed handlers

Each static operation has a proposed owner and destination in actions.csv. Retain the old symbolic name and numeric alias as migration identity, independently of display labels and a future host-owned action key. Store the source context separately: G global, S Grid, E Editor, V Video, A Audio; historical N/W map to S/V. Numeric range and `GetType` are not an eligibility matrix. [Loader/writer](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/Hotkeys.cpp#L237), [context aliases](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/ConfigConverter.cpp#L587).

The five route columns describe source accelerator installation and explicit cross-bindings, **not proven end-to-end dispatch**. G has menu-presence and range conditions. S/E/V cross-bind other window domains. A builds a separate table and also contributes some bindings to Grid. Video IDs2000–2003 additionally enter Grid. Audio ALT IDs retain separate identity while Grid connects their handler at ID+10. Source branches and unresolved cases are retained in the exception table. [Tab routes](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/TabPanel.cpp#L100), [Audio routes](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/AudioBox.cpp#L587), [Global routes](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/HikariSubFrame.cpp#L1754).

Grid Ctrl-X/C/V, Editor NumEnter/Ctrl-NumEnter and plain Enter, native text editing and numpad digit interception are installed separately. Their presence does not establish duplicate-chord precedence. The Editor-context Grid branch appears unreachable in source; Global Audio dispatch can fall through to Video when Audio is absent. Treat these as source anomalies awaiting fixtures, not accepted desired behavior or authorized fixes. Protected targets, modal ownership, IME, format, selection and media requirements need operation-specific eligibility checks; this worksheet does not claim those have been exhaustively executed.

Dynamic macro IDs begin at30100 and are reassigned while reading; saving uses script Name. Preserve filename/ordinal/name evidence, raw binding and context, leaving missing/colliding/reordered scripts unresolved. Do not execute scripts during import. Two converter aliases, Plus5SecondG and Minus5SecondG, target absent GLOBAL_5_SECONDS_FORWARD/BACKWARD symbols. They remain unresolved, with no guessed Video substitute.

## Decisions and verification boundary

Use the existing [settings/import proposal](settings-import.md) for preserved inputs, revision-bound review, repeat-import receipts and rollback. This worksheet neither activates those policies nor changes the accepted storage decision. The highest-impact open groups are:

1. **Import conflict policy and C04:** keep-current versus reviewed replacement, handling a valid short file, malformed values and ambiguous encoding. C04-short-file still needs named approval; old loader/converter rewriting must not be invoked to inspect inputs.
2. **Routing:** intentional local/global overlap, focus/modal precedence and treatment of observed routing anomalies. Preserve each source context and fixed handler until characterized; no blanket local-before-global rule is accepted.
3. **Representation reconciliation:** positional profiles/legacy inactive keys, old geometry/backend requests and dynamic macro identity. Retain unresolved records visibly instead of silently losing capability or selecting a nearest name.

Checks covered exact registry/default counts, unique symbols/IDs, required columns, CSV parsing, declaration-line identity, and bounds for source anchors. Input hashes and result counts are recorded. The worksheet uses the pinned research checkout consistently because the primary checkout's HikariSubFrame.cpp has since changed. No legacy user settings were opened, no importer or application was run, no source was rewritten, and no runtime precedence, import idempotency, rollback or cross-platform compatibility pass is claimed.
