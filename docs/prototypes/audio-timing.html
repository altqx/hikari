What to try · what is still a proposal

Drag across the waveform for an audition selection; drag yellow S / E handles or type exact milliseconds for the draft Line. Commit to update the grid; Revert to discard. Turn on Karaoke, split “sail ” after character 2, adjust a duration, join again, then move the Line start: centisecond durations remain relative to it.

Inspect the protected Reference from the Audio target menu: selection, navigation and audition still work; timing and karaoke writes are disabled. Returning to Editing restores its pending draft. The Editor and bottom grid always identify the Editing document.

Review: Which Audio hierarchy works best: A local strips, B audition rail, or C task-first? Is separate audition selection useful, or should it follow draft boundaries more tightly? Should the proposed auto-commit/advance rules change?

In Audio outside a text/number field: S / Space audition, R whole Line, H stop, Z / X previous/next Line (syllable in Karaoke), Q / E / D / W 500-ms windows, T to end, A / F scroll, B go to selection, C / V lead-in/out, G / Enter commit. Timeline Left / Right nudges the chosen draft edge; Shift uses 1 ms. Numeric fields are alternatives to every timing drag. F6 / Shift+F6 visits Video → Audio → Editor → Grid. Variant arrow keys apply only to the bottom switcher or the page background.

Keyframes are synthetic 25-fps indices. Draft snapping uses legacy GUI representatives, not frame-start timestamps. Drag snapping has a proposed 10-pixel radius; Shift temporarily bypasses it. Both Audio edges use the start-frame representative, as in the inspected Audio code; this is not the inclusive end-frame input control. Numeric entry does not snap. No production gesture/tie-policy parity is claimed.
