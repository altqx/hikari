# Video and visual typesetting study

Throwaway prototype for [#55](https://github.com/altqx/hikari/issues/55), prepared 2026-09-27. Open [video-typesetting.html](video-typesetting.html) directly in a browser. No server, external assets, dependencies, account or network connection is needed. All state is in memory and disappears on reload. Root handles browser QA, publication and recording the human reaction; this note records no acceptance of the proposed interactions.

## Question and alternatives

How should Video expose playback and visual tools without losing the accepted Compact Studio / Classic composition? All variants keep Video at approximately 44% on the left of the upper workspace, Audio above Editor on the right, and the full-width grid below. Narrow screens stack these panels. The variants change hierarchy **inside Video**, not the accepted palette or overall layout.

| URL | Video hierarchy | Tradeoff to review |
| --- | --- | --- |
| `?variant=A` (default) | Named tool rail beside the canvas; numeric inspector below | Simultaneous tool discovery, at the cost of a narrow rail. |
| `?variant=B` | Tool strip above; numeric inspector beside the canvas | Stable visible parameters, at the cost of canvas width. |
| `?variant=C` | Named tool selector; canvas; task and transaction shelf | More canvas space and explicit edit sequence, fewer visible tools. |

The floating switcher retains model state and writes only the URL query. Background/switcher Left and Right change variants; focused fields and canvas keep their own keys. The dark, light and contrast appearances use the accepted semantic palette. Browser rendering does not establish native OS scaling, high-contrast or assistive-technology support.

## Review walkthrough

1. In **Position**, drag the Position handle or edit Feature X/Y. The Editor shows the pending tag sketch beside the committed sketch. Commit updates the named pending Editing Line IDs; Cancel discards all pending visual drafts. Undo restores the previous committed batch **and its prior drafts**. This explicit-commit policy is proposed, not established legacy behavior.
2. Navigate between L1 and L2 without committing. Drafts stay associated with stable sample IDs. Grid checkboxes select batch targets independently from the active Line. After Position shifter or Hydra creates drafts, changing the checkbox selection does not retarget those existing drafts. The transaction label names the IDs that Commit will affect.
3. In **Move**, click the canvas to set a crosshair, choose a sample time/frame, and capture A; repeat for B at a later time. From/To are milliseconds relative to the Line start. Numeric endpoints and times remain editable. Reversed/equal times are displayed for review; their simple preview interpolation is not an accepted malformed-input or quantization rule.
4. Try **Scale**, **Z rotation**, and **X / Y rotation**. Scale has a draggable corner and numeric percentages. Z has an origin, angle handle and two-click angle operation. XY changes draft values and an illustrative guide only; it does not reproduce ASS perspective. Escape cancels a pending two-click angle without discarding earlier drafts.
5. In **Rectangle clip**, draw in empty canvas space or move a corner; invert the clip. In **Vector clip** or **Drawing**, select an endpoint or Bézier control in Feature, drag it or type coordinates. Choose Add line / Bézier / spline / separate point, then click the canvas or Apply at crosshair. Move-points mode does not add a point. Delete operates on the selected endpoint and preserves at least two sample nodes. Splines display control polygons, not libass curves.
6. Load Rectangle or Arrow, edit points, name and save a memory-only preset, then load it again. Drawing activates a filled SVG path; it does not import, export or parse arbitrary ASS shapes. Preset replacement is a sample rule, not an approved collision policy.
7. Select L1 and L2 and use **Position shifter**. Position, Move A/B, clips, drawing points and origins are separate options. Drawing-point mode excludes Position/Move to avoid the double-motion combination warned about by the legacy UI. Try **Hydra** Add and Insert on `fs` or `bord`; inspect both affected Line drafts. Other tag values update the sketch; multiply and gradient modes are explicitly retained but disabled in this sample.
8. Switch Target to **Protected reference**. Visual writes, Commit, Cancel and Undo are disabled and guarded; coordinate inspection, view changes and transport remain available. The ordinary Editing target and its drafts remain intact. This small reference sample follows the active Editing Line index; independent reference navigation/comparison is outside this artifact.
9. Expand **Source, streams, chapters, snapshots and viewport**. Change video/audio/subtitle selections, chapters, aspect, SAR, zoom and pan. Switch between indexed editing and general playback: the silent animation stops, a sample generation changes, and drafts remain. General playback disables exact frame controls. The intended clock/audio owner is labelled separately from the actual browser animation clock.
10. Open **Fullscreen layout**. Inspect its transport, sample monitor label and toolbar visibility; Escape returns focus to the launcher. This is an in-page dialog, without OS fullscreen or display enumeration. Preview the four raw/subtitled save/copy snapshot choices: they freeze an SVG in memory; no PNG file, OS clipboard or source deletion occurs. Try No video / Decoder failure to keep coordinate tools usable without media.

F6 / Shift+F6 traverses Video → Audio → Editor → Grid. Tab follows DOM order; B's visual rearrangement remains a specific focus-order review item. With the canvas focused, arrows nudge the selected feature by one script unit (Shift: ten). Numeric fields provide endpoint/control alternatives. Escape restores a pointer gesture to its pre-gesture draft, rather than cancelling all accumulated drafts. These are sample interactions, not a production shortcut-routing or accessibility acceptance result.

## Coordinate and state boundaries

The fixed synthetic source is 1920×1080. The initial script plane is 1280×720. For a script point, the prototype scales into source coordinates, applies sample pixel aspect ratio (or the explicit display-aspect override), fits to the canvas, applies zoom and centered letterboxing/pan, and obtains logical view coordinates. Pointer input uses the inverse of that same chain. Handle circles are drawn outside the scaled content group and stay 12 logical pixels in diameter. The live readout names Script, Source and View rather than conflating them.

Script-size controls change this example mapping without resampling stored values; they do not approve a production resolution-change policy. Pan values are logical view units. Source crop, source rotation, device-pixel-ratio conversion, tablet pressure, native hit-testing tolerances and mixed-monitor behavior are not implemented. Point edits preserve floating values in the model; the tag sketch rounds to two decimals for readability. That rounding is **not** an accepted ASS serializer rule.

The 12-second transport uses a simple synthetic 25-fps frame index and integer microsecond sample position. Frame stepping visits the sample frame start; it does not implement the separate start/end frame-entry representative or VFR conversion rules in the [time contract](https://github.com/altqx/hikari/blob/qt/docs/qt/time-semantics.md). A browser animation supplies the silent cursor; no media or audio clock is measured. The six Line-action seek choices and four after-seek choices exercise simplified sample rules. “Audio to Line end” has the same silent animation here, not independent audible behavior.

The Editor's tag text is a generated **sketch of structured sample values**, not an editable ASS parser, lossless serializer or production command. The overlay shows the active Line as a typesetting aid even outside its time interval. It does not reproduce event visibility, font fallback, shaping, text metrics, vertical alignment, style inheritance, inline overrides or multiple simultaneous Lines. Drawing points are previewed directly in script space with Z rotation; complete ASS position/scale/origin composition is not reproduced. Those limits must not be mistaken for renderer behavior or approved changes to it.

## Capability coverage and remaining work

All eleven active legacy visual families have a selectable interaction or explicit numeric/guide representation. A family being present is not proof of all its modes or parity.

| Existing capability | This artifact | Still required; no removal proposed |
| --- | --- | --- |
| Crosshair / coordinate copying | Shared transform, numeric values, sample clipboard | OS clipboard formats, coordinate precision and real video geometry. |
| Position | Handle/numeric point; X/Y axes; rectangle placement; alignment selection | Actual ASS alignment metrics, multiline text, override locations and full selection behavior. |
| Move | Two endpoints, relative times, capture at two sample positions | Native frame acknowledgement, complete time semantics, multiple move tags and malformed-time characterization. |
| Scale | X/Y percentages, linked axes, corner/bounds guide, reset | Real text/drawing bounds, custom original rectangle, change-all-tags and preserve-position modes. The guide assumes a 360×70 script-unit text box. |
| Z rotation | Origin, angle handle/numeric angle, two-click angle | Change-all-Z-tags and preserve-position/proportion modes; full renderer-equivalent origin geometry. |
| X/Y rotation | Numeric values, origin and illustrative guide | Actual ASS 3D projection, perspective clipping and change-all-XY-tags. |
| Rectangle clip | Drag rectangle/corners, numeric bounds, enable/invert | Exact integer/float serialization, tag ordering and interaction with arbitrary imported overrides. |
| Vector clip | Endpoints, cubic controls, line/Bézier/spline/separate/delete modes, inversion | ASS spline evaluation/closure, multiple subpaths/winding, valid command parsing and curve hit testing. Spline entries deliberately show their control polygon. |
| Drawing | Same point editor, original shapes, fill preview, presets | ASS drawing scale/baseline/transform rules, renderer parity, raw-path editing/import/export and arbitrary imported shapes. |
| Position shifter | Selected IDs; deltas applied to structured position/move/clip/drawing/origin fields | Full parser/tag-instance coverage and legacy group/hidden/selected-Line policies. |
| Hydra / all-tags tool | Sample Add and Insert/replace for six values; `fs`/`bord` visible | Configurable tag definitions and slider rules, cursor insertion, multiply/multiply+, increasing/decreasing text and Line gradients. Disabled modes are retained capabilities. |
| Shape management | Original Rectangle/Arrow, memory-only save/replace/load of current path | Full create/edit dialog, raw ASS text, restore defaults, persistence and preset schema/migration. |
| Source / general player | Original source choices, previous/next sample, failure/closed/dummy, explicit mode/owner labels | File/open/recent/folder workflows, indexing/progress/cancel, real streams, decoder fallback and native mode handoff. |
| Tracks / subtitles / chapters | Video choice changes illustration; subtitle choice changes sample overlay; audio selection is state; chapter navigation | Native metadata/capabilities, actual track selection, chapter adapter, embedded subtitle styles and avoiding double composition. |
| Transport | Silent play/pause/stop, exact sample frame steps in indexed mode, numeric time/frame, ±5s/±1min, Line boundaries, Audio marker, volume/progress and seek-policy controls | Audio, decoder seeks, VFR, queue invalidation acknowledgement, stop tails, clock uncertainty, drift and keyboard parity. |
| View / fullscreen | SAR/aspect/zoom/pan/script dimensions; in-page full view, sample monitor and toolbar control | Native fullscreen/window restore, monitor changes/DPI, screenshot pixel policy, resampling decisions and cross-platform window behavior. |
| Snapshots / source removal | Four raw/subtitled save/copy previews; coordinate sample clipboard; remove from sample view | File formats/destination, OS clipboard, real source deletion/recovery and explicit destructive-action UX. |

The commented-out Scale/rotation-shifter toolbar slot is recorded as an inactive source remnant, not an active twelfth tool or a newly accepted feature. Optional Windows DirectShow and CSRI/xy-VSFilter capabilities remain in scope; this cross-platform browser study neither enables nor removes them. No new general-purpose plugin interface is proposed.

## Evidence, checks and decisions still open

The [complete UI inventory](https://github.com/altqx/hikari/blob/6f91fd28eab4c42d2c00f848606b47585c2b6bc8/docs/research/ui-inventory.md) and [visual overlay research](https://github.com/altqx/hikari/blob/fb510f491048b3a073ace4076cf12bc949345c53/docs/research/visual-overlays.md) are the main capability and coordinate references. The active families and inactive slot are visible in [VideoToolbar.cpp](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/VideoToolbar.cpp#L104); its position/scale/rotation/vector/shift/Hydra item implementations supply the submode ledger. [VideoBox.cpp](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/VideoBox.cpp) and [VideoFullscreen.cpp](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/VideoFullscreen.cpp) supply player/fullscreen context. These are source observations, not fresh runtime parity tests.

The accepted [media ownership contract](https://github.com/altqx/hikari/blob/qt/docs/qt/media.md) keeps FFMS2/libass required, PortAudio editor output, and the general player as owner of its own audio and clock. Qt Multimedia remains the first general-player candidate to verify. The separate [native probe report](../../HikariSub/prototypes/media-handoff/report.html) and [notes](../../HikariSub/prototypes/media-handoff/README.md) exercised only bounded existing-Windows-FFMS2 decode/metadata/PCM/cancel behavior. Qt Multimedia could not import and no PortAudio binary was available in that scoped runtime; no native clock handoff, QSG/libass composition, Linux, performance or color result follows from it or this HTML.

Executed here: inline JavaScript syntax; 71 unique static IDs; ten ad hoc model/DOM-stub scenarios covering draft/commit/cancel/undo, stable pending IDs across selection changes, protected-reference write guards, relative Move captures, forward/inverse mapping under SAR/aspect/zoom/pan, path/control/preset edits, shift exclusions and Hydra targets, gesture/angle cancellation, simulated mode changes, and tool/snapshot render paths. These are disposable smoke checks, not a committed test suite or real-browser interaction/layout verification. No real media, audio device, GPU, native fullscreen, OS clipboard or file operation was exercised. Browser geometry, pointer capture, actual focus traversal and all human judgments remain for root QA/review.

Minimal review choices: **A, B or C for Video-internal hierarchy**, and **explicit Commit for visual drafts versus one undoable edit on gesture release**. The latter is a proposal requiring a deliberate choice, not implied by accepting Classic. Parameter ranges, rounding, malformed geometry, batch scope, preset collision behavior and the omitted legacy submodes still require characterization or named decisions. Keep #55 open until the human has reacted; neither the mockup nor this ledger approves dropping a capability.
