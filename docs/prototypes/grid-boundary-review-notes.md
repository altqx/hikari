## Walkthrough and questions

1. **Hidden interior row:** A/H/B, H hidden, anchor A. Inclusive membership selects A/H/B; displayed-only selects A/B. H stays hidden in both. Apply, inspect the hidden count, Undo or Reset, and compare. Preserve the characterized inclusive rule unless a change is requested; this is not another required vote. Already-retained hidden selection is a separate accepted rule. This fixture fixes current-moving-on-selection and does not decide hidden/deleted-anchor fallback, Ctrl-addition or display-only sorting.
2. **Group boundary:** D/A/B form one group; C is ordinary. Duplicate A produces D/A/A-copy/B/C and remains valid. Move A after C previews the broken flag run and the proposed guard rejects without content, selection, revision or Undo mutation. Review explicit Remove group: it deletes description D and leaves members as ordinary Lines. Acknowledging that named loss enables Apply. Then review Move again; removal does not silently execute it. Undo each operation. Is that proposed reject/remove/retry outcome appropriate for an actual break? No general structural validator or automatic repair is implemented.
3. **Join:** default A/B/X/C selects A/B/C. Both alternatives combine only A/B/C text and spanning times into A. The source-derived interval deletes B/X/C; the selected-only proposal deletes B/C and preserves X. The source simulation requires acknowledging X's deletion. Switch to **two selected · control case**: A/X/B selects A/B, and **both delete B only and preserve X**. This correction matters: the source deletes from the *second* selected row through the last; a hidden or unselected row between the first and second selections is outside that interval. Should the three-selected operation preserve X? This does not approve unrelated Join properties, translation or group rules.

## Checks

Both inline scripts parsed. Nine bounded model result records covered the two range memberships, valid duplication, unchanged content/selection/revision/Undo on rejection, separate removal/move/Undo, and both Join modes with two versus three selected Lines. The two-selected modes both retained X; only the three-selected source interval removed it. These were direct observations of the fixture module, not an added formal test suite.

In the in-app browser, inclusive Apply showed A/H/B with one hidden selection; displayed-only showed A/B with none. Duplication preserved D/A/A-copy/B/C. Attempted group-breaking Apply kept revision1 and one Undo entry. Remove group Apply stayed disabled until the description-deletion acknowledgement; it then removed D, and the separately reviewed move changed the order. Undo restored the pre-move order. The three-selected source Join removed X; Undo and selected-only Join retained X with its original text. The two-selected source preview correctly listed only B as deleted. Escape closed its review without applying. Browser error log inspection returned no errors.

Actual browser captures of the overview, explicit description deletion and three-selected Join review were visually inspected and saved as temporary handoff images outside the repository. The Classic core geometry and full-width Grid were visible; the task dialogs fit the desktop viewport without overlap. No narrow-window, assistive-technology or production parity pass is claimed.
