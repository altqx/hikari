# Document utilities task-dialog study

Throwaway, memory-only prototype for [#60](https://github.com/altqx/hikari/issues/60). **Human reaction is still required.** It asks where options, captured targets, before/after changes and results belong for Script properties, numeric resampling, Font collector and MKV extraction. It does not select production APIs or approve draft, collision, extraction-target or staging policy.

Open [document-utilities.html](document-utilities.html) directly. No installation, server, persistence or permissions are required. A uses simultaneous options and review; B uses staged Options and Review/results pages. Switch inside the dialog or with `?variant=A` / `?variant=B`. The outer bottom switcher is available while no modal is open; arrow keys switch variants only outside interactive controls and the modal. Both preserve accepted Compact Studio colors and Classic video-left/audio-editor-right/full-width-Grid geometry. The background media and Grid are contextual illustrations.

Every source, font identity, track, destination and output is invented. Buttons do not open a picker, inspect installed fonts, access a filesystem, decode media, write a ZIP or contact a service. Closing or reloading loses state. A separate native evidence link is clearly identified; it does not qualify the current selection.

## Suggested walkthrough

1. **Metadata versus resampling:** choose the setup, review 1280×720 → 1920×1080, Run, Simulate next staging step, then Publish to memory. Only resolution metadata changes; Line positions, text and times do not. Close and inspect the live state. Reset, open Resample, choose 1920×1080, and compare the visible/hidden Line positions and Style values. An unchanged-aspect fixture scales position 100,200 to 150,300; its 1–3 second timing stays unchanged. Change aspect ratio to compare no-stretch/stretch. These are structured numbers, not parsed ASS tags.
2. **Resample draft collision:** this setup has pending text. Run is withheld until an explicit reconciliation choice. “Commit named drafts” commits that fixture text and rebuilds the review; it requires another Run. Cancel after that commit preserves the separately committed text. “Discard” retains the draft until publication; cancelling staging leaves it intact. Open Demo controls to switch Editing: the captured target remains Harbor. A target revision change or newly staged draft blocks publication until review is rebuilt.
3. **Incomplete font collection:** inspect captured, fallback, missing request, missing glyph, simulation and unknown variable-instance rows. Run is withheld until partial output is explicitly allowed. The existing Harbor.ttf defaults to Skip; choose Keep both to produce Harbor (2).ttf. Choosing Create on an existing name is rejected. Run, step both eligible items, then Publish. The result still says **Incomplete**, including after all eligible files are copied. Change to Check only for no output, or to MKV attachments for **Attachment only; renderer agreement unverified**. All-open scope includes protected sources read-only; an included Document without sample MKV prevents attachment collection rather than inheriting another tab's media.
4. **Extraction and cancellation:** T1 plus F1/F2/F3 starts selected. Existing and duplicate Harbor.ttf candidates default to Skip; the subtitle and Signs.otf remain eligible. Run, stage one item, then Cancel. No new Document or output appears. Rebuild, stage all, and Publish to create one new unsaved Document descriptor and the attachment fixture. Try Keep both for both Harbor attachments, file-output mode's existing English.ass, and an unnamed attachment. “Corrupt sample” fails after a staged item and discards staging. No-text and unsupported codec/type cases are explicit.
5. **Protected replacement:** the setup captures Reference.ass and proposes replacing it. Review is allowed; mutation is blocked. A normal target's replace mode requires exactly one selected subtitle track and names the loss of its current content. New-Document mode preserves that source. To exercise freshness, stage a normal job and then change the destination revision, source revision, draft or font generation using Demo controls; publication is blocked.

Staging is deliberately stepped by hand so the user can inspect cancellation and stale-state boundaries. It is not measured progress or a background-worker implementation. Zero-output metadata/check operations still use one step to expose their publication boundary. Finished, failed and cancelled operations require a rebuilt review before another run.

## Deliberately proposed mechanics

- A utility captures its target when opened. Prepare freezes source revisions, draft snapshots, font-generation values and destination revision. Editing-tab changes never retarget it. Options remain editable, but the prepared values stay frozen until Prepare/rebuild; publication choices are frozen when a run starts. A competing revision is detected, not automatically merged. Full property-field rebasing remains unimplemented.
- Metadata edits do not reconcile unrelated text drafts. Numeric resampling and content replacement name a conflicting draft. Read-only collection may use committed content while retaining drafts. Explicit draft commit creates a separate fixture change and rebuilds review; discard happens only at publication. This is not acceptance of #43 or editor/audio draft policies.
- Collisions start at Skip. Create cannot overwrite an existing destination; Replace explicitly permits that named fixture overwrite; Keep both allocates a distinct name. Two active items cannot resolve to the same path. Existing outputs remain untouched during staging. Logical publication is all-or-nothing within this tiny synchronous model; native durability is still a separate obligation.
- All-open font collection reads protected Documents without changing them. A captured source-folder root is shared by this demonstration job; it does not implement per-Document output-folder routing. Different Document environments remain distinct synthetic identities even when filenames coincide. Partial copying never upgrades the diagnostic to complete.
- MKV replacement is a proposed, explicitly destructive Document-content choice, separate from destination-file overwrite. New extracted Documents are only unsaved result descriptors; the demo does not implement their editor tabs or full parsed content. Safe-basename candidates and unique-name choices are shown before publication; cross-platform reserved names, case sensitivity, normalization, symlinks and canonical destination checks remain native work.
- The synthetic microsecond fields exercise unchanged timing only. They neither prove the accepted signed-64-bit implementation nor upgrade imported precision. Unknown source metadata is retained in the fixture; this is not a byte-preserving parser/serializer result.

Eight bounded in-memory observations passed: metadata/opaque preservation; resample draft rebuild and unchanged timing; incomplete-output and overwrite guards; cancellation; late-draft staleness; protected replacement; failure without partial publication; and all-Document font-generation freshness. These are synthetic logic observations, not a formal suite, native verification or browser QA. Human reaction and root browser/layout review remain pending.

## Focused reaction

Choose A/B or a combination for options versus review. Assess whether metadata-only resolution and numeric resampling are unmistakable, whether partial font output remains visibly incomplete, and whether the proposed captured-target/draft/collision review has enough detail without hiding routine actions. New-Document versus replace/file extraction and staged cancellation still need a product verdict. None of these questions reopen accepted renderer authority, protected-reference rules or Classic geometry.

## Root browser observations

At the default 1280-pixel viewport, incomplete font output was rejected until explicitly allowed. Keep both assigned Harbor (2).ttf, two items staged and publication retained the Incomplete result. Cancelling extraction after one staged item reported no published outputs or Document changes. Metadata-only 1280×720→1920×1080 had a distinct review and published one Document command; the structured preview explicitly preserved Line geometry and timing. Resampling rejected unresolved drafts; an explicit draft commit rebuilt its preview rather than applying the resample immediately. Protected replacement disabled Run. A side review and B staged results were visually inspected. A presentation-only defect was fixed and rechecked: terminal published/cancelled/failed results no longer show an active stale-plan warning merely because their own publication advanced destination state. Model freshness guards remain active for review/running/staged work. No native files, font identities, parsing or a complete utility parity matrix was tested.
