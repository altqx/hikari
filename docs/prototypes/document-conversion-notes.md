# Format conversion review study

Companion to [Prototype Script properties, resampling, Font collector and extraction dialogs](https://github.com/altqx/hikari/issues/60), whose scope now includes the complete conversion workflow. **Throwaway; human reaction pending.** Open [document-conversion.html](document-conversion.html) directly. No server, installation or external access is needed. Use `?variant=A` for options beside a change ledger, or `?variant=B` for staged options and a full-width review/output view. The floating switcher and dialog buttons retain the same memory state while changing presentation.

The surrounding Compact Studio / Classic shell keeps Video left, Audio above Editor right, and the full-width Grid below. The primary task body is capped at 500 logical CSS pixels with local scrolling. All subtitle text, catalogs, metadata, media rates and results are invented. No input file, real catalog, font, codec, filesystem, clipboard or network is accessed. Reload resets everything.

## Review boundary

Accepted [C02 loss review](https://github.com/altqx/hikari/blob/752588a7f8146f4bd94bf9b185524875d8672af9/docs/qt/compatibility-decisions.md) requires explicit acceptance of the listed losses and retention of the source Document. Options/source changes invalidate a captured plan. Accepted per-Document MicroDVD rate isolation and format precision are inputs, not questions being reopened.

**Still proposed:** A/B presentation; a separate unsaved converted Document versus an export-preview destination; the placement and remembering of conversion options; draft reconciliation; explicit text-role/fallback projection. Creating a sample result does not approve these policies. The protected source can be read to derive a separate copy; no protected or ordinary source can be overwritten by conversion. The explicit draft-commit demo action is a separate source edit and invalidates the conversion review.

The output is an illustrative Unicode string, **not a valid-file or byte-round-trip assertion**. ASS output deliberately describes the chosen Style rather than emitting a complete Style record. New Document results are inspectable memory descriptors, not integrated editor tabs or saved files. The source tab and source contents remain available.

## Bounded walkthrough

1. **ASS losses / duplicates:** inspect the twelve source Lines, including comment, hidden/grouped Line, duplicate, drawing, `\p0`, karaoke and positioned sign. Prepare SRT. Comments, markup changes, broad drawing-rule loss, earlier-duplicate removal, empty-row cleanup, metadata loss and precision are listed separately. Creating the result is unavailable until loss acceptance. Afterwards inspect the retained source tab and the result descriptor in full state.
2. **SRT → ASS settings:** choose a catalog/Style, Script width/height and Line prefix. Prepare; see the chosen Style descriptor, metadata and converted markup. Resolution here creates ASS metadata; it does not resample geometry. Switch the target to each of MicroDVD, MPL2 and TMPlayer to see format-specific output. Same-format Save is explicitly a separate workflow.
3. **MicroDVD unknown rate:** the source retains raw frames and has no FPS. Review is blocked. Enter input rate `25`, rebuild and inspect 25 source frames becoming 1000 ms; the original frame fields remain intact. Output FPS is a separate explicit value. Choose FPS from video and use the media demo toggle: a VFR/no-single-rate context cannot silently become CFR. Decimal `23.976` is not silently substituted with `24000/1001`.
4. **TMPlayer end synthesis:** the source has no authored ends. Change ms/character and prepare MPL2 or SRT. End synthesis and previous-end trimming appear as changes; the source remains start-only. The optional new-end setting does not synthesize stored ends when exporting TMPlayer from other formats.
5. **Pending draft:** Wait blocks conversion. Explicitly choose committed content to retain/exclude the draft, or use the separate Commit source draft control and rebuild. Neither choice is an approved transaction policy. No automatic commit occurs.
6. **Captured/stale/protected:** prepare and accept, then change source revision, draft, catalog generation, options or media context. Creating a result is rejected until rebuild and renewed acceptance. Switching Editing alone does not retarget the source. The protected-source setup permits a separate derived copy; demo attempts to edit/commit that source are blocked.
7. **Cancellation / repeated entry:** Cancel discards the current review and creates nothing; earlier results remain. Close retains source/results. Clear Show options, close and reopen: the next entry prepares the mandatory unaccepted loss review; Show options restores the controls. This preference is memory-only and does not skip C02. Result creation cannot publish the same plan twice.

Source anchors:

- [Whole-grid conversion](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/SubsGridBase.cpp#L199): optional preference dialog, FPS-from-status, global FPS validation, comment deletion, duration synthesis, ASS metadata/Style creation and old-format sorting/cleanup. Sorting happens **after** duration synthesis. The dedupe key omits Style, Actor and translation; it removes the earlier equal row. Empty removal starts at index 1.
- [Per-Line conversion](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/SubsDialogue.cpp#L935): converts `Text`, not `TextTl`; ASS resets layer/Actor/margins/effect and chooses conversion Style. The broad `\p[0-9]+` match empties even `\p0` text. Nested MicroDVD/MPL2 tests inside the SRT-target branch cannot succeed. The sample makes those risks visible; it does not approve repairs.
- [Conversion controls](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/OptionsDialog.cpp#L473): catalog/Style; editable FPS choices; FPS-from-video, New end times, Show window; 30–1000 ms/letter; 1–3000 dimensions; arbitrary ASS prefix. [Style lookup](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/config.cpp#L703) has cached/default behavior which the synthetic catalogs do not reproduce.
- [Time serialization and conversion](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/SubsTime.cpp#L83): ASS 10-ms truncation, SRT milliseconds, MPL2 ceiling to tenths, TMPlayer seconds and MicroDVD frame storage/ceil paths. The [accepted typed time contract](https://github.com/altqx/hikari/blob/752588a7f8146f4bd94bf9b185524875d8672af9/docs/qt/time-semantics.md) governs the rewrite; this small JavaScript model uses bounded millisecond samples, not signed-64-bit core values.

No blanket converter fix follows from C02. In particular, reproducing the visible `\p0` loss for a fixture, blocking unresolved fallback inputs or choosing a role projection is not an accepted production disposition. The blank ASS Y fallback writes X in the inspected source; this study requires explicit valid dimensions and records the unimplemented path instead of silently presenting a corrected fallback as legacy behavior.

## Observations and next decisions

Both inline scripts parse. Thirteen bounded model observations passed: twenty format-pair preparations with unchanged sources; mandatory loss acceptance and single publication; five independent stale-input guards; unknown input-FPS handling; target precision/rational distinction; protected-source copying; pending-draft exclusion; TMPlayer previous-end trimming; separate comment/duplicate/`\p0` loss reporting; ASS settings; VFR-rate rejection; captured target through an Editing switch; and mandatory review when options are hidden. These are memory-model checks, not a formal test suite or a parser/serializer parity result. Browser QA, native dialogs/input/accessibility and human reaction are still required.

React to A/B organization, the separate converted-Document versus export-preview destination, and the clarity of excluded drafts/loss categories. The source-preserving C02 contract, Classic geometry, PortAudio, text-editor/IME policy and protected-reference ownership are not being reopened.

## Root browser observations

Browser review on 2026-09-27 confirmed that ASS to SRT creation stayed disabled until the six listed loss/change categories were explicitly accepted. Creating the reviewed result produced a separate unsaved Harbor-converted.srt and retained the Harbor.ass source. The missing MicroDVD input rate blocked review and result creation; cancellation reported no new result. The SRT to ASS scenario exposed the selected Harbor/Title Style and exact prefix in its illustrative output. Changing the captured catalog generation after acceptance invalidated creation until rebuilding. Both A and B were visually inspected and captured. A's initially overflowing options fields were corrected to remain inside their column and rechecked. These are synthetic browser observations; no native parsing, encoded file, durable write, complete format parity or policy approval follows.
