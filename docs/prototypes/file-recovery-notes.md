# File operations, Sessions and recovery study

Throwaway prototype for [#61](https://github.com/altqx/hikari/issues/61), prepared 2026-09-27. Open [file-recovery.html](file-recovery.html) directly in a browser. There is no server, dependency, network, filesystem, browser storage, download, clipboard, notification or update API. Every path, file version, write, corruption flag, task and outcome belongs to an invented in-memory model. Reload resets the study. Root owns browser QA, publication and recording the human reaction.

## Question and two presentations

How should optional Home and file/recovery tasks make the target, pending work, failures and next action visible without disrupting the accepted Editing workspace?

| URL | Presentation | Tradeoff to review |
| --- | --- | --- |
| `?variant=A` | Optional Home cards for Recent, Session and Recovery; task controls remain inline below Classic | Workspace context remains available while resolving drafts, but the page grows vertically. |
| `?variant=B` | Compact Home rows; file tasks open in a focused browser dialog over Classic | A task has a clear attention boundary, but resolving an Editor draft requires returning to the workspace and reopening the task. Prepared state remains. |

Both preserve Compact Studio and Classic: Video left at approximately 44% of the upper workspace, Audio above Editor on the right, full-width grid below. The Home checkbox hides or restores Home. Nothing here chooses a startup preference or makes Home mandatory. The floating A/B switcher changes the URL and retains model state. A direct B URL begins with its compact Home; choosing a task opens the dialog. On narrower screens the workspace and task columns stack.

The shared tasks/results table remains part of the workspace, with job identity, captured target, state and diagnostic. It records manually driven model transitions; it is not a background-worker, notification or performance demonstration. Help includes the same task log. Theme variants use the accepted dark/light/contrast tokens; native scaling and assistive-technology behavior remain unverified.

## Walkthrough

1. **Open / reload:** choose the SRT fixture, Stage open, then Activate. Staging creates a result without changing an existing Document. The corrupt and missing inputs fail visibly and retain existing work. Replace captured target / Stage reload require a current writable target, an unchanged capture and an explicit pending-work disposition. A source changed after staging invalidates activation. The raw/unknown source excerpt is a model field, not a real parser result.
2. **Missing media:** open a fixture with missing media, or use Retry failed media. Subtitle editing remains available. Relink updates the sample resource generation; Remove association clears it. Neither rewrites authored times. Protected resource associations cannot be mutated. The illustration and waveform are original static context, not decoded media.
3. **Save / Save As:** edit and commit the first Line, then Prepare preview. The plan names the Document, lifetime/content/draft revisions, destination, format/encoding, draft inclusion, newer-edit choice and injected outcome. Authorize replacement and Deliver injected outcome are separate steps. Save As changes the associated path and saved snapshot only after Written success. The default draft choice requires resolution in Editor; committed-only and commit-before-prepare are explicitly unaccepted alternatives.
4. **Save outcomes:** select disk-full failure before preparing: delivering it retains the previous target, path and saved identity. Cancel before authorization revokes the unused permit. Cancel after authorization reports Waiting, because it cannot promise absence of a write; deliver the actual injected outcome. A post-replacement uncertainty creates/replaces the mock file but does not advance the saved identity or satisfy close-by-Save. These are semantic examples, not real filesystem durability results.
5. **External changes:** the guided scenario changes bytes/version while leaving the displayed modification time unchanged. The old preview rejects authorization. Use another destination, or explicitly review overwrite and prepare anew. Changes after authorization are checked again before model replacement. Opening another Document on that destination after authorization also blocks replacement under the conservative, unaccepted collision guard.
6. **Export:** choose original/translated text, explicit empty-translation fallback, output format and encoding. Preview lists sample tag/style/unknown-section loss, fallback and timing quantization. Accept those enumerated losses before authorization. The `1009 ms` start demonstrates ASS `1000`, SRT `1009`, TMPlayer `1000`, MPL2 `1100` without changing the source value. ASCII representability blocks multilingual output rather than silently substituting bytes. These are illustrative mappings, not encoded subtitle files. Export never marks the source saved and requires another destination. A protected reference can explicitly export a copy, but cannot Save or rebind itself.
7. **Save all / close:** Prepare close review captures the entire open set and pending work. Choose Save, Discard or Cancel per Document. Resolve choices may complete some saves, but does not close tabs. A later failed/cancelled save leaves every Document open; earlier successful saves remain. Finalize close rechecks the captured lifetime/content/draft set. The guided stale-choice scenario inserts a new draft after Discard approval; finalization must reject it. Changing a resolved choice to Cancel or Pending invalidates resolution. Authorized writes must finish before another save or close resolution.
8. **Session:** stage the four-entry fixture. Activate checked ready entries alongside existing work; two entries remain missing/corrupt and visible. Make the missing source available, restage and retry. Existing matching open Documents are reused without overwriting their content or silently changing a writable role to protected. Omitted Audio comes from the entry's own context or none, never a prior entry. An unresolved pin remains explicitly unavailable. Explicit omission is a review action, not automatic silent omission.
9. **Recovery:** the newest proposed bundle is corrupt. Open as unsaved copy rejects it. Use the newest valid family fallback: it creates a new unsaved Document with provenance and its recovered draft still pending. Original and recovery objects remain. Legacy subtitle snapshots have no invented manifest or stored drafts. This fresh-copy behavior is the proposed **L58-recovery-copy**, not approved legacy parity.
10. **Cleanup:** choose a family, age/all ages and explicit legacy inclusion, then inspect the exact candidate IDs. The model keeps active resources and a family's last valid recovery. Mark a candidate active after preview to see Apply reject the changed permission. Removal deletes only checked model objects; no real file is touched. Source subtitles, Sessions, settings, dictionaries/catalogs and external fonts are outside the cleanup model.
11. **Help / updates:** try Disabled, available, offline and incompatible-result fixtures, stable/beta selection, reminder and release-details entry. Offline failure is distinct from “up to date”. Every response is an authored example; no current release fact is asserted. Website, issue reporting, credits and reminders are preview entries only. Nothing opens a page, submits a report, schedules a reminder, downloads, installs or restarts.

In A, F6/Shift+F6 traverses Video → Audio → Editor → Grid → task → shared results. B uses the browser dialog's focus containment; Return/Escape closes only the task view and returns focus to Editor. Task closure is not job cancellation. Pointer, actual focus, modal behavior, geometry and native AT/IME still require root browser QA and later Qt verification.

## Accepted contracts versus unaccepted behavior

The accepted [Document model](https://github.com/altqx/hikari/blob/qt/docs/qt/document-model.md) distinguishes content/source preservation, stable identity, resource context and application state. The accepted [time contract](https://github.com/altqx/hikari/blob/qt/docs/qt/time-semantics.md) owns quantization and frame provenance. The accepted [distribution policy](https://github.com/altqx/hikari/blob/qt/docs/qt/distribution.md) selects optional notification-only update checks, channels and explicit user action for the release page. A browser demonstration proves none of their native implementation gates.

The [lifecycle proposal at the reviewed revision](https://github.com/altqx/hikari/blob/f105d7946d1ce1c5c9fb924f0e278beaa1638d23/docs/qt/proposals/application-lifecycle.md) and [draft/command proposal](https://github.com/altqx/hikari/blob/05bde108b52e5a7e40ebac71dc9abc6a843b38dc/docs/qt/proposals/edit-transactions.md) are **unaccepted**. The study illustrates:

- **L58-write-close:** close only after acknowledged success covering the reviewed pending work; cancellation/failure keeps Documents open.
- **L58-staged-replacement:** failed/cancelled open, reload or replacement retains old work.
- **L58-recovery-copy:** recover into an unsaved copy, leaving originals and recovery candidates untouched.
- Explicit draft inclusion choices, whether newer edits may continue after authorization, partial Session activation/omission, unavailable pins, same-destination collisions and cleanup/retention guards.

The parent's proposal now explicitly binds close choices to lifetime/content/draft state and leaves open-destination collision policy pending. This model conservatively revalidates close decisions and blocks collisions. Layout acceptance would not approve these write/close or retention changes. **C02 loss preview, C03 unknown/raw preservation and C05 per-entry Audio association are already accepted named outcomes**; no broader parser, malformed-input, export-fallback or lifecycle fix follows implicitly.

## State and model limits

A Document has a unique sample ID, lifetime generation, content revision, separate draft revision, source path/version, saved snapshot and permission. Prepared open/write/close work captures those values. Late source changes, new drafts, closing or permission restrictions invalidate the applicable operation instead of retargeting it to the focused tab. Protected tabs can be inspected; ordinary Editing identity is not promoted when one is viewed or closed.

“File fingerprints” are model content/version strings. They demonstrate why timestamp equality is insufficient, but do not implement file identity, hashes, aliases, symlinks, hardlinks, case normalization, network filesystems, race-free replacement or cross-process compare-and-swap. The collision check compares exact sample path strings only. The model is single-threaded; Authorize/Deliver exposes a conceptual boundary, not native lock/permit ordering.

Before authorization, write validation requires the captured content/draft state. After authorization the default holds sample edit publication; the explicit newer-edit alternative permits changes while only the written snapshot becomes saved. Prepared choices remain frozen when controls later change. Authorized writes block overlapping save/close/reload operations. Actual worker drains, decoder releases, render-thread resources, shutdown marker publication and native cancellation races are absent.

The sample stores two typed Lines and an opaque source string, not a full record/section parser or byte-preserving encoder. Export retains original fields alongside a separate `exportText` mapping for inspection; it does not produce a valid ASS/SRT/MPL2/TMPlayer byte stream. Same-format opaque content remains in the modeled file object. Unknown/raw reuse after arbitrary edits, field encodings, BOM/newlines, malformed records, source spans and large-file limits still need fixtures. MicroDVD/SSA/plain-text conversion is listed as retained below rather than given invented semantics.

A Session summary here records sample associations/roles; it is not `.kls` serialization and cannot restore a legacy undo stack or unsaved editor buffer. The proposal's future recovery bundle can hold a separate draft, but that does not change legacy Session/autosave grammar. Recovery validity/checksum failures are injected labels, not actual checksum/parser execution. Active cleanup references are conservative model flags, not a proven refcount/release implementation. Count/size/age defaults, 0/1 autosave capacity, discard versus recovery deletion and post-close retention remain unresolved.

## Root browser observations

Reviewed A inline tasks and B focused dialog at the default 1280-pixel viewport. Injected save failure left every Document open and prevented final close. An external destination fingerprint change prevented replacement authorization. Partial Session activation restored two ready entries while preserving two unresolved entries and per-entry Audio isolation. A corrupt recovery candidate was rejected; newest-valid fallback created a separate Recovered Harbor copy with pending work. A new draft after a resolved close choice caused final close rejection. These browser observations complement the author's bounded model checks; they do not test actual filesystems, serializers, crash recovery, native dialogs or every close race.
