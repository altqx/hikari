# Search, replace and review study

Throwaway prototype for [#57](https://github.com/altqx/hikari/issues/57), prepared 2026-09-27. Open [search-review.html](search-review.html) directly in a browser. It is self-contained, with no server, network, dependency installation, dictionary or filesystem access. All subtitle documents, file paths, words, rules, clipboard content, drafts and history are invented memory-only state; reload resets them. Root owns publication, browser QA and recording the human reaction.

## Question and alternatives

How should persistent Search share scope and results across find/replace, select-lines, spelling and correction rules while keeping the operation target and proposed changes clear?

Every variant keeps the accepted Compact Studio palette and Classic composition: Video left at approximately 44% of the upper workspace, Audio above Editor on the right, full-width grid below. Search occupies an additional persistent tray below that workspace; this study does not replace the grid or reopen the accepted theme/layout choice. Its precise dock placement remains part of workspace implementation and review.

| URL | Search hierarchy | Tradeoff |
| --- | --- | --- |
| `?variant=A` | Scope/query strip, task results, then checked change review | Familiar reading order, with more vertical distance between expression and Apply. |
| `?variant=B` | Scope rail on the left; task results and change review on the right | More space for scope controls, less width for text comparisons. |
| `?variant=C` | Change review first, task results below, scope rail on the right | Prepared changes remain prominent; new users must locate query controls beside them. |

The floating switcher updates the URL and preserves state. Dark/light/contrast are included. Narrow screens stack the tool sections. DOM order remains scope → task → review even when C visually puts review first; native focus order and whether that mismatch is acceptable need review. F6 cycles Video → Audio → Editor → Grid → Search; Shift+F6 reverses it. Browser control semantics are not native Qt accessibility verification.

## Walkthrough

1. In Find / replace, search `harbor`. Find all gives result context, document, stable sample Line ID and text role. Click a result or use Previous/Next. Inspection does not silently change Editing; **Make this document Editing and go to Line** is explicit and disabled for protected references and mock external files.
2. Preview replace all, inspect before/after rows, uncheck a row, then Apply checked. The preview freezes the target IDs, source values/revisions and operation parameters. Changing Search's target or grid selection does not retarget the prepared changes. A new preview uses the current controls. The small Recent query list restores expression/scope options; it is application/tool state, separate from Document command history.
3. Pin Search to Harbor titles, then make Notes Editing. Search retains the pinned target. Follow Editing restores following. All-open scope explicitly includes the two writable documents plus the protected reference. Protected results can be read, but preview rows are excluded and guarded even against a forced checked state.
4. Use **Set up draft conflict**. The pending Editor original text differs from the committed text that Search read. Apply reports the affected document/Line and changes nothing. Discard that field draft to permit the old preview, or Commit it and rebuild the now-stale preview. Navigating tabs/Lines retains drafts by Document/Line/field. This reconciliation behavior is proposed under #43, not accepted merely because it runs.
5. Select a text role or metadata field; try literal/regex, case, whole-word, beginning/end, text/tag region, dialogue/comments, hidden Lines and style eligibility. Start/end fields are formatted sample strings for searching/selecting only; replacing typed timing with arbitrary strings is deliberately not simulated. Both text roles are searched separately; the sample never concatenates them into a hidden replacement buffer.
6. Choose External files. Folder, extension filter, subfolder and hidden-folder options select only the three built-in mock file objects. Preview and Apply modify those objects in memory. No file is enumerated, opened, backed up, overwritten or deleted. Mock file changes still name their targets and revisions.
7. Select Lines supports With/Without, Select/Add/Remove/Toggle matched and the same field/scope eligibility. Copy writes matched original text into the sample clipboard. Set as comment creates another checked Document-change preview after updating selection. Cut, move-to-beginning/end and delete remain visibly listed as retained, unsimulated capabilities. Toggle matched is a review alternative; the inspected legacy dialog itself offers Select, Add and Deselect.
8. Spelling → Scan sample finds only authored typo fixtures. Select a result/suggestion, edit replacement text, and preview replacement of one or all matching fixture occurrences. Ignore once, Ignore all, add a personal word, and remove a personal word all work in memory. English fixtures cover `teh`, `harbr`, `recieve`; the Polish fixture covers `zegluj`. Unlisted words are not asserted correct. Language choice changes this tiny fixture map, not a loaded Hunspell dictionary.
9. Correction rules exposes ordered enabled rules, description, regex, replacement, match case, replacement case and region. Add/delete/reorder/edit or enable/disable rules; changes affect authored state only. Preview enabled or selected rules to see per-stage effects and the unresolved alternative. Existing previews retain their captured rule definitions until rebuilt.
10. **Set up AA → A / cat → dog** selects the comment fixture and enables its eligible scope. The source-offset sketch produces `A cat`; the sequential proposal produces `A dog`. Switch Evaluation and inspect the chain. With From first selected, the source-eligibility sketch yields no eligible rule results, while the sequential proposal exercises the intended scope. Neither difference is an approved fix.

Undo document command affects only the current Editing document, not personal words, rules, query history or another document's command. This is a limited in-memory undo demonstration, without redo, persistence, coalescing, native composition or a production history cap. It conservatively blocks Undo while that document has pending field drafts. A multi-document preview produces separate document history entries; it does not establish an application-wide atomic history contract.

## Model and compatibility boundaries

Search reads committed source values. Results capture document/Line/field, source revision, original string and match range. A prepared change revalidates identity, permission, document revision and source value before applying. Conflicting field drafts block Apply. This sample prevalidates all checked rows before any write; that behavior and its cross-document failure policy remain proposals, not approved replacements for legacy partial-outcome behavior. Unchecked protected rows are not modified, and a no-change comparison row cannot be applied just to manufacture a history entry.

The selected scope, field and role are explicit. Current selection and From first selected refer to stable sample IDs in current sample order, not the legacy grid's mutable source/visible indices. No-selection From first selected yields no rows in this study. Hidden sample rows remain visible in the small context grid with a label so the reviewer can see why eligibility changes; this is not a production filtering proposal.

The matcher uses JavaScript `RegExp` with Unicode/global flags and optional case-insensitivity. Literal input escapes regex characters. Whole-word checks use adjacent Unicode letters/numbers/underscore; they are not wx word-boundary or linguistic segmentation proof. Region filtering checks brace context at the match start, not a full ASS syntax tree; cross-boundary matches remain a characterization case. Matches are non-overlapping, capped at 150 per field, and zero-width scanning advances by a code point. Offsets remain JavaScript UTF-16 offsets. Empty ordinary searches return no matches, while Select Lines can match an empty field against an empty expression. These choices are **sample bounds/semantics**, not accepted production behavior.

Replacement supports a small JS-style `$&`, `$$`, `$1`–`$99` substitution subset. It does not convert legacy wx backreferences, named captures, replacement case rules or unsupported constructs. A bad JS pattern leaves the Document unchanged and reports an error; legacy invalid-regex handling differs by tool and remains to be characterized. Arbitrary wx scripts/rules must not be migrated by substituting this matcher.

Spelling uses hand-authored word/suggestion pairs and Unicode-letter tokenization. The shared matcher/region switches are disabled in Spelling; it always skips brace-tag content. Correction rules use their own per-rule options instead. Spelling does not reconstruct words split by tags, Hunspell encoding/affixes, suggestions, RTL reversal, combining-range mappings, language fallback or dictionary caches. Ignore state is session-only. Personal words and ordered rules represent authored resources; their actual `UserDic.udic` and `Rules.txt` bytes, order, flags and encoding remain unchanged by the rewrite commitment. This artifact performs no import or save.

### The correction-rule source discrepancy

The pinned [replace loop](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/MisspellReplacer.cpp#L502) initializes each rule's `text` from original `lineText`, yet extracts/replaces at those offsets in `stringChanged`; subsequent matches within that rule scan a suffix of the changed string. A length-changing earlier rule can therefore make the next rule's initial offset refer to another substring. The ASCII fixture models that flow: after `AA` shortens, the original `cat` offset selects `at`; reapplying `cat` to that fragment makes no replacement. This is a **source-derived JS sketch**, not a reproduced wx runtime result for arbitrary rules.

The same code sets its starting row for scope value 2 (From selected), but the eligibility predicate accepts only 0, 1 or 3. The [find loop](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/HikariSub/MisspellReplacer.cpp#L377) has the same omission. The sequential mode is an explicitly unapproved candidate that evaluates each rule against current output and permits the intended From selected scope. It does not authorize either fix. The [compatibility contract](https://github.com/altqx/hikari/blob/qt/docs/qt/compatibility.md) requires a named decision per defect or enumerated batch; approving a general policy did not approve this candidate.

The draft/command policy follows a reviewable version of the [proposal](https://github.com/altqx/hikari/blob/05bde108b52e5a7e40ebac71dc9abc6a843b38dc/docs/qt/proposals/edit-transactions.md), not an accepted transaction ADR.

Executed: inline JavaScript syntax and static-ID checks, plus twelve disposable model/DOM-stub scenarios covering matcher bounds; preview/apply/Undo; draft conflict and stale previews; follow/pin and frozen targets; protected writes; synthetic external-file filtering; selection/comment preview; spelling/personal state; the correction offset/scope counterexample; rule snapshots; and all mode/variant render paths. These are not a committed test suite, actual browser interaction tests, wx runtime fixtures or native performance/input validation. Root browser QA and human reaction remain open.

Minimal questions: **A, B or C for Search hierarchy?** Does checked bulk review with explicit target adoption and draft conflict resolution communicate the operation clearly? A layout reaction does not approve regex replacement, correction fixes, selection policy changes, dictionary persistence changes or the still-open command transaction policy. Keep #57 open until the human has reacted and the remaining boundaries are recorded.

## Root browser review

At the default 1280-pixel viewport, Find/replace changed exactly the two eligible Harbor fields (including a tagged field) in one document history entry. A pending draft caused Apply to reject with no change; explicit discard plus a new preview allowed the correction. Protected results were excluded and Apply disabled. Spelling prepared the exact harbr→harbor correction, and document Undo reported restoration. After switching Editing to Notes, pinned Search still prepared Harbor IDs at its captured revision. The AA/cat fixture displayed A cat for the source-offset sketch and A dog for the unapproved sequential proposal. A/B/C layouts were visually reviewed with the same retained preview. These checks do not establish wx regex, all selection/file modes, real dictionary behavior or native accessibility.
