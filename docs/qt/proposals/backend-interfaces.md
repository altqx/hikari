# Proposed backend interfaces and resource ownership

For [Define backend interfaces, capabilities and resource ownership](https://github.com/altqx/hikari/issues/62). **Proposal, not an implementation or newly accepted backend/process policy.** Follow the accepted [architecture](../architecture.md), [typed time](../time-semantics.md), [media/audio](../media.md), [fonts](../fonts.md), [platform](../platform-policy.md) and [distribution](../distribution.md) contracts. The [lifecycle](application-lifecycle.md) and [transactions](edit-transactions.md) proposals remain proposals, including their named departures. Their draft, save, close and undo choices are not implicitly approved here.

## Shared value boundary

Application ports use standard C++ value records, typed times, optional values and explicit result variants. Core knows subtitle/time values and algorithms; it does not depend on these services. Qt/native-library handles remain inside adapters. UI models translate values into Qt properties; QML delegates never call a decoder, font provider or device directly.

Every asynchronous request captures RequestId, DocumentId where relevant, Document lifetime/content revision, ResourceId/source generation, adapter-instance generation and configuration generations actually used. TrackId belongs to one source generation; indexed FrameId belongs to one indexed timeline. General-player timestamps do not manufacture exact indexed identities. Device identities are scoped to their enumeration/backend; names alone are not stable identity.

Resource descriptors retain requested location, resolved identity, provenance and identity confidence. A basename/mtime cache hit is insufficient proof of source equality. Reopening, track replacement, device loss or adapter restart advances the appropriate generation without reinterpreting authored Document times. C05 still forbids borrowing Audio from a preceding Document.

Capabilities describe operations, supported formats/limits, prerequisite state and unavailable reasons. Separate advertised support from verified runtime/package qualification. Exact indexed seek, time seek, track selection, chapters, subtitle suppression, CPU frames, native textures and output-quiescence evidence are separate entries. MissingDependency, Unsupported, UnavailableResource, InvalidInput, Stale, Cancelled, Busy, DeviceLost and BackendFailure remain distinguishable; EOF is a normal result. Diagnostics retain stable codes plus safe contextual values and backend details, with localization owned by the application.

An immutable BufferLease owns storage until all consumers release it. It identifies byte count, layout, generation and release route; dimensions/strides/ranges are checked before publication. No borrowed FFMS2/libass pointer escapes its callback lifetime. Across processes, transfer a versioned descriptor and owned copy or validated shared-memory lease, never a C++ pointer, Qt object or library handle. Shared memory requires producer/consumer release and crash cleanup; it is not assumed zero-copy.

## Media and rendering ports

Conceptual signatures below specify outcomes, not a frozen C++ ABI:

| Port | Inputs and results | Ownership contract |
| --- | --- | --- |
| IndexedSource | open(SourceRequest) → tracks, index progress, timeline/provenance; frame(FrameIndex) → Frame or EOF/error; audio(SourceSampleRange) → PCM blocks. Index requests capture track/decoder/seek settings. | One adapter owner serializes native calls. Frame includes index, rational source PTS/origin, optional duration, planes/strides, pixel format, geometry/SAR/crop and separate range/matrix/primaries/transfer metadata. Exact requests use the accepted FFMS_SEEK_NORMAL direction and acknowledge the requested identity or error. |
| GeneralPlayer | open, selectTrack, seek(MediaTime), play, pause, stop; events return selected tracks, actual delivered timestamps, buffering/state and clock estimates. Chapters may come from a companion metadata port. | The active general player owns audio and A/V scheduling. A time-seek result identifies requested and delivered positions plus accuracy/unknown duration. A position notification alone cannot acknowledge a matching frame. Its audio is not routed through editor PortAudio. |
| SubtitleRenderer | prepare(DocumentRenderSnapshot, FontEnvironment, RenderConfig); render(time, geometry) → ordered overlay masks/owned pixels, change region and font diagnostics. | Snapshot names committed revision or an explicitly authorized draft-preview identity/text role. The application chooses inclusion; rendering cannot commit drafts. Renderer owner serializes libass contexts, copies transient output, and retains font/attachment leases until context destruction. |
| FontService | enumerate/resolve(requested names, style/glyph requirements, environment); collect(snapshot, scope) → files/faces, missing requests/glyphs, fallback/simulation and completeness status. | Resolution identifies actual bytes/hash, collection face, available instance coordinates and provider/config generation. Authored names remain unchanged. Picker candidates and Qt samples are not renderer proof. Separate Document environments prevent equal attachment-name leakage; duplicate/system precedence remains characterized behavior. |
| Presenter | offer(FrameLease, OverlayLease, transform, presentation generation) → accepted/superseded/error; completion events identify the consumed frame and evidence stage. | UI/application publishes immutable presentation descriptions. Qt render-thread owner creates/uploads/destroys graphics resources and never waits for decoding. Visual-tool geometry is separate; both use the same forward/inverse transform. A new window/device generation rejects stale uploads and releases resources through their owner. |

Keep owned decode completion, scene consumption, GPU completion and physical display observation distinct. A CPU reference render and QSG presenter should expose comparable frame/color/alpha metadata, not claim equivalence from matching barcode identity. Native textures are an optional later capability requiring graphics-device compatibility and explicit synchronization/release; the initial owned CPU-BGRA/libass reference remains required. Blank/disappearing overlays invalidate previous pixels even when video stays paused.

Font diagnostic hooks return owned provider bytes and opened-face identity, not a cache-local UID presented as a persistent identity. Font/attachment/provider changes create new environment generations, invalidate reports and recreate affected contexts. In-flight consumers retain their old bytes until release. Collection success requires verified agreement; unresolved fallback or instance identity yields incomplete output, not a generic success boolean. Optional CSRI/VSFilter requires its own evidence.

## Editor audio, analysis and caches

AudioDecode produces immutable PCM with source sample rate, channel layout, sample format, source range/origin and applied processing identity. Output preparation negotiates device format and explicitly records resampling/channel/delay mappings. Source sample frames, device frames and monotonic time remain distinct types. AudioOutput opens a named/default device through PortAudio, accepts prepared bounded buffers and reports lifecycle events plus clock estimates with domain, epoch and uncertainty.

The real-time callback consumes ready buffers, fills remaining output with silence and records bounded lock-free status. It performs no allocation, reclamation, disk read, logging, Qt dispatch or decoder work. Retire leases and drain telemetry on the control thread. Underrun, seek, device replacement and suspend invalidate the estimate; a clock must not extrapolate stale data indefinitely. Source-range audition keeps its half-open range and silence outside it. Resampling tails, variable/reverse scrub and fades remain explicit unresolved semantics.

Analysis requests identify source range, resolution/channel policy and, for spectrum, FFT/window/hop parameters. Results are immutable min/max peaks or magnitude tiles with exact covered range and generation. QSG waveform geometry and cached spectrum textures remain the accepted direction; recoloring does not recompute magnitudes. Selection/cursor redraw is independent of analysis.

Cache keys include verified source identity, selected track, decoder build, format/rate/channel/delay processing and analysis parameters. Partial results advertise coverage; incomplete files never masquerade as complete PCM/index/tile caches. Activation and cleanup use file-service permits from the lifecycle proposal. Lease-pinned entries survive eviction until release. CPU/GPU/disk budgets are explicit, measured and bounded under the accepted [performance gates](../performance.md); this proposal invents no qualifying queue size or memory result.

## Scheduling, cancellation and handoff

Each owner has a bounded request queue and byte budget. submit returns Accepted(RequestId) or Busy/Unsupported, rather than allocating indefinitely. Latest-view requests may supersede queued work with an explicit terminal Superseded outcome. Accepted exact frame requests cannot silently become a different frame. Playback can drop late frames under the transport policy. Coalesce progress display; retain terminal outcomes and report diagnostic truncation counts.

Application publication runs on its serialized state owner. Completion validates captured identities, dependencies and target permissions; following/pinned tools never retarget pending results implicitly, and protected references remain non-mutable. Media failures preserve subtitle editing. Workers do not acquire application history authority. Cancellation requests cooperation; exactly one terminal outcome resolves each request, while resource release can complete later. A cancelled observer cannot free buffers still used by a decoder, callback or GPU.

For mode switch: stop admitting old playback work; request stop/flush; invalidate its clock/source generation; record the actual output-quiescence acknowledgement; resolve the destination source and time mapping; present the requested indexed frame or honestly reported general-player result; then authorize the new audio/clock owner. Distinguish logical Stopped, callback ceased, backend buffer release and measured device tail. Unknown flush/tail is an unresolved qualification gate, not success hidden inside a generic stop boolean. Do not weaken the accepted handoff requirement by treating timeout as drain.

Shutdown revokes new work, cancels/drains tasks, stops transport, then releases renderer/font/device/graphics leases on their owners. Retain owners until release completion; do not kill an in-process native worker. Helper crash closes its generation and pending requests; a replacement instance cannot accept old replies. Restart/reopen and device-follow policy stay explicit user-visible recovery choices in their existing surface reviews. Mutating file/cache activation still requires final write permission; ignoring late callbacks alone cannot prevent a stale write.

## Platform ports and packaging

Platform services expose values and asynchronous completion without putting OS types in core:

- Dialogs/clipboard/external-open: GUI-affine requests with initiating Document/run identity, typed accept/cancel/error results and surviving focus-return target. User-selected paths are values with provenance, not authorization for unrelated writes. Preserve synchronous Lua-facing behavior through the accepted bridge; never block the GUI waiting on a helper that needs a GUI reply.
- Paths/files/integration: installed user-data/config/cache/recovery roots versus explicit portable sibling data; checked read/write/replace results; optional handler registration, repair and removal. Windows defaults are not forced, portable integration is explicit, and user-owned data survives uninstall. File dialogs do not silently resolve collisions between open Documents.
- Process/metadata services: explicit executable/package identity, argument vector, working context, progress/exit/result distinctions for extraction, chapters and external muxing. Process-start success is not completed output. Preserve backend availability and cancellation diagnostics; no invented general extension SDK.
- Update checks: platform/package/channel/version inputs → available/current/offline/failed/incompatible. Preserve disabled checks and reminder behavior; only user action opens the validated release page. No automatic download/install/restart. Diagnostics report build/plugin/library identities, generations and bounded traces; export is deliberate and excludes secrets/unrequested document content.

Composition selects audited built-in adapters and explicitly supported optional Windows DirectShow/CSRI adapters. Optional does not mean automatic fallback or a general plugin ecosystem. Deployment manifests enumerate Qt plugins and dynamically loaded native libraries/helpers; package checks reject conflicting or missing runtime dependencies. Windows/Linux qualification and future macOS ports remain separate evidence obligations.

## Evidence, alternatives and review frontier

The [pinned media research][video-research] and [audio research][audio-research] motivate these seams. The [4012f2ec Windows continuation][native] observed Qt track selection/subtitle suppression, owned FFMS frames, software presentation and 19,968 zero-filled PortAudio frames. CFR 1000 ms initially delivered frame 24 before 25; VFR 1035 ms delivered frame 23 at 1040 rather than containing frame 22. Its 100-ms near-window criterion is not product seek semantics. It did not prove GPU/libass/color equivalence, acoustic drain, real source-PCM playback, Linux or calibrated performance.

That run loaded different hashes of same-named FFmpeg DLLs in separate processes. It proves neither safe coexistence nor inevitable failure of every rebuilt bundle. **Recommend qualifying an isolated FFMS2 media worker first**, with Qt general playback in the application process. This avoids relying on unproved coexistence, at the cost of IPC copies/leases, startup, memory and packaging. Keep it independent of Lua's helper lifetime. Alternative: engineer a common compatible FFmpeg build/dependency closure and qualify both adapters together in-process. Selecting either direction requires measurement and loader/license audits; a successful Python child probe is not a shipping ABI or process decision.

1. Approve the proposed value/capability/ownership contract, including distinct completion evidence and explicit unavailable outcomes? Recommended. Concrete C++ classes, protocol encoding and measured queue capacities remain implementation choices within it.
2. Prefer isolated FFMS2 media-worker qualification or a shared FFmpeg build first? Recommend isolation as the initial production direction **conditional on** transfer, performance, packaging and recovery proof. No silent fallback between these architectures.

Native follow-ups must qualify cancellation/late completion, helper loss, exact seek, source PCM/resampling/device loss, presentation/color/alpha, renderer-selected font-byte leases, concurrent refresh, loader origins, clean package startup and bounded resource growth. The [font experiment][font-native] had 17/18 captured-set reimports match; multilingual fallback reconstruction remained incomplete. Interface approval cannot convert that result or any software/callback observation into full compatibility, collection completeness or release qualification.
