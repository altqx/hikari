# Translation operations: captured change study

Throwaway, memory-only companion to [Prototype translation mode and protected comparison navigation](https://github.com/altqx/hikari/issues/49) and [Prototype Line editor metadata, ASS controls and completion workflows](https://github.com/altqx/hikari/issues/63). Open [translation-operations.html](translation-operations.html) directly. There are no dependencies, network requests, file dialogs, native clipboard calls or persistence; reload resets the authored specimens. The source/input textarea changes memory only.

The question is whether users can understand the exact Original/Translated, row and timing changes before applying a translation operation. This is a logic study using the **accepted stacked fields, full-width Grid and independent bottom reference**. It asks no new overall-layout question. Video and Audio are illustrations. Desktop height is bounded; Editor and task content scroll locally.

The page uses a pure, DOM-independent `TranslationStudy` block and a separate browser shell. Neither is production code. The application will remain the owner of real commands, history and drafts; this example does not settle those contracts.

## Walkthrough

Each guided tab resets to known input. Its ordered buttons perform the actual memory actions, and the task footer repeats the next button while a task is open. The ordinary operation buttons remain available for free play.

1. **Mid-line tags:** open Moving tags, build the review, acknowledge/stage, then close and commit. The raw specimen `{\i1}Quiet {\b1}harbor{\b0}{\i0}` becomes Original `Quiet harbor` and Translated `{\i1}{\b1}{\b0\i0}`. Both fields are staged, while committed Grid data is unchanged until Commit. Undo restores the prior source. Inspect the leading-block caret index in the retained selection readout. A4 also contains a plain `{note}` block: the source algorithm does not limit itself to valid ASS overrides.
2. **File text / hidden rows:** build the paste review. It begins at the first displayed row, regardless of Current or selected rows. A3 remains hidden and unchanged; seven incoming strings map to five visible rows and append two Original-empty rows with Start/End `0/0`. Inspect each before/after pair, apply, close and Undo. Switch the traversal to all rows to compare the captured mapping.
3. **Six alignment operations:** reveal the rows and anchor A2. The guided Original-join removes A2 after joining its Original with A3 using `\N`; A3 keeps its identity and receives A2's earlier Start. A tail row is added by the source branch. Undo restores the prior rows. Free play exposes all six role/action combinations; inspect Original, Translated, IDs and timing, not only the operation's label.
4. **Bulk / draft collision:** selected A1/A3 includes hidden A3 when explicitly enabled. The guided per-row-own-Original alternative is labelled proposed. A pending A1 draft holds the review. Explicit discard is a separate action, then the review must be rebuilt; Cancel itself never discards. Compare with the same-current-value broadcast alternative before applying.
5. **Stale / named target:** capture Harbor's paste, then switch Editing to Signs. The task still names Harbor. A competing Harbor revision invalidates the old preview; attempted Apply changes nothing. Rebuilding binds the current Harbor state. A successful application changes Harbor only, while Signs remains Editing.
6. **Preserved quirks / protection:** the narrow SRT sample imports its first cue only. Its final accumulator remains visibly unflushed, matching the inspected path rather than inventing a corrected EOF flush. Protecting the captured Document prevents Apply. Cancelling retains the source, content and drafts.

Current-Line Copy all and Copy selection are also reachable beside the text fields. Select Original text, then select a Translated range: the selected Original substring is **inserted at that range's start**, without deleting the selected Translated text. The sample “Select harbor” button supplies a reproducible source selection. Copied text stages the editor draft; it does not silently publish a Document command.

## Source audit

All inspected source files match the pinned legacy commit `20d647c4c769ab7f5d383cf3c1c33f03876a94e9`; the local comparison showed no differences for these four files. The [complete UI inventory](https://github.com/altqx/hikari/blob/6f91fd28eab4c42d2c00f848606b47585c2b6bc8/docs/research/ui-inventory.md) establishes the retained translation family. This is source analysis, not an executed legacy oracle.

Numeric text ambiguities and malformed inputs are held. This is not native reproduction, a defect approval or permission to silently drop the final cue in the rewrite. |

Filtered and larger-offset cases remain held because the source combines physical indices, visibility and offset lookup. The source's upward branches can remove empty-Original tail rows, while nonempty Original at the tail reduces the removal count and can retain duplicated translation. Adding an Original row clones anchor metadata before text realignment. Original-join prepends source Original with `\N`, copies the earlier Start and deletes the source row; translation movement and appended rows occur alongside it. These effects are visible in the change list, not normalized into idealized whole-Line commands. Exact larger-offset, hidden-row, comment/group and boundary outcomes need characterization.

## Explicit review policies

- The task captures Document, current Line, settings/source generation, content revision, draft generation and selection/visibility generation. Switching Editing does not retarget it. Content, draft, scope or source/settings changes make the review stale. Applying rechecks those tokens and protection, and uses the frozen changes rather than recalculating from new input.
- Current copy and Moving tags stage a draft. Bulk copy, paste and alignment publish one reviewed memory command. An overlapping retained draft blocks those commands; the example offers explicit discard and rebuild. It does **not** choose the production reconciliation policy or automatically commit/discard pending work.
- Before/after acknowledgment names replacements, added/deleted rows and timing changes. It is a review mechanism for reaction, not a newly approved mandatory confirmation on every real operation.
- Protected targets reject drafting, stage/apply, Commit and Undo. Reference navigation/copy remains independent and only changes a sample buffer. Unconfirmed is preserved by these text operations. Ordinary Enter outside composition commits/advances in displayed order without implicit confirmation; actual OS IME behavior remains the native editor gate.
- The history is at most eight complete row snapshots. Undo requires no retained drafts and the latest applicable revision. Revisions remain monotonic after undo; old plans do not become valid again. No coalescing, production saved-point identity, pruning, redo or durable history is claimed.
- Memory state includes complete rows, IDs, timing, Styles, Unconfirmed, visibility/selection, current roles, retained drafts, plan ownership/generations and preserved source input. Added identities are synthetic; they are not proposed serialized Line IDs.

## Coverage and exact remainder

| Family | Representative workflow now available | Remaining depth / decision |
| --- | --- | --- |
| Mid-line tag movement | Gather blocks, adjacency merge, both field changes, empty-translation guard, staged versus committed result | Arbitrary ASS, malformed lexical paths, drawing/escape behavior, native offsets/IME, combined multi-selection edits and production draft semantics |

| Translation file paste | Preserved input, two traversal choices, replacement/appended rows, source quirk preview, cancellation/staleness | ASS/SSA/SRT/MicroDVD/MPL2/TMPlayer parsers, encoding/BOM/extension casing, conversion order, exact Style/metadata defaults and native final-cue evidence/disposition |

| Ownership and guards | Captured named target, protected reference, draft conflict, stale source/content/scope, explicit cancel and memory Undo | Final application transaction/lifecycle choice, native focus/announcements, real clipboard/files and durable cancellation/history |

No gap removes an existing capability. Full comparison/matching, export role/fallback and TLMode serialization remain in their existing studies/specification; this companion does not settle them. ## Evidence and focused reaction

Both inline scripts parse. Nine disposable pure-model observation groups passed: mid-line stage/commit/undo; paste hidden-row preservation and zero-time append; all six one-slot branches; filtered/wide shift refusal; draft collision/reconciliation; stale revision with unchanged captured target; protected/no-ack rejection; insert-without-replacement; and final SRT accumulator omission. No formal suite, legacy execution, real file, native rendering/IME/accessibility, byte-round-trip or performance check was added.

Root browser review on 2026-09-27 observed Moving tags staging both roles before Commit and Undo; paste skipping hidden A3 and appending two zero-time rows; Original-join removing A2, preserving A3 identity with the earlier Start, and Undo; disabled bulk Apply with a retained draft, followed by explicit discard/rebuild; stale Apply rejection after a competing revision while Editing switched to Signs; successful rebuilt application to Harbor only; and protected-target rejection plus cancellation retaining source. The terminal-status wording was corrected so a completed operation does not describe its own resulting revision as a stale active review. [Workspace capture](translation-operations-preview.png) and [tag-review capture](translation-operations-review.png) show the bounded layout. This is representative browser QA, not complete keyboard or native accessibility qualification. Human reaction is required.

The useful reaction is whether **the role-specific action names and exact row/timing review make these operations understandable**, and whether **the distinction between same-current broadcast and each-row bulk copying is clear and desired**. This does not ask for the accepted stacked layout again or obtain blanket approval for the source quirks, candidate fixes or draft/history policies.
