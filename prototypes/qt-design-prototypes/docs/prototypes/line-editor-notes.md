# Line editor controls study

Throwaway, memory-only study for [Prototype Line editor metadata, ASS controls and completion workflows](https://github.com/altqx/hikari/issues/63). **Human reaction is required before resolving the UX question.** Open [line-editor.html](line-editor.html) directly; it needs no installation, server, files or dictionaries. Everything resets on reload. Only the explicit evidence/companion links navigate elsewhere; the page does not fetch resources or invoke clipboard, search, font, media or persistence APIs.

Compare `?variant=A` **Control bands** against `?variant=B` **Local inspector**, using the bottom switcher. A keeps metadata, text and tags in successive full-width bands. B keeps text beside a narrow Line/Tags/Review inspector; every metadata field remains reachable. Both retain accepted Compact Studio/Classic geometry: Video left, Audio above Editor right, full-width Grid below. Original stays above Translated, with an optional independent protected reference tray below the Grid. These variants do not reopen the accepted overall arrangement. On desktop, the upper workspace is bounded to approximately 463 pixels including the Audio row. The Editor scrolls locally while its owner, commit controls and status remain visible, so Video does not stretch to the height of every control. A opens on Text with section-jump buttons for Line properties and ASS controls; B has independent text/inspector scrolling. This is an adjustable prototype starting size, not a production fixed-window requirement.

## Walkthrough

1. **Tags and selection:** choose Wrap selected text, which preselects `quieet`. The active role and retained range are visible in state. Bold/Italic wrap that source range; Undo draft restores its exact prior fixture string. Place a caret in ordinary Raw dialogue, try Font/size, all four numeric color slots/ASS alpha, and alignment. The video remains a committed-text illustration, not libass output. Try searching `position`, `fs` or `fade` in completion, toggle descriptions and the inventoried visual/VSFiltermod groups, then insert a template. Ctrl+Space from a text field focuses this search; Tab reaches result buttons. Enter in text remains Commit + next; completion buttons use normal button activation.
2. **Metadata and drafts:** change actor, timing or margins. The Grid still shows committed values. Enter in a text field commits the Line and advances; Commit stays; Commit + confirm explicitly clears Unconfirmed. Enter alone does not confirm. An invalid end-before-start or margin value retains the draft and current Line. The last fixture Line stays current rather than inventing another Line. Duration explicitly changes End relative to Start in this sample.
3. **Departure alternatives:** choose Draft and target change, then Next. The Ask alternative offers Commit/Discard/Stay. Switch to Retain per-Line draft, visit another Line or Document, then return and inspect the original pending actor value. Commit-on-departure is also a review alternative, with the same validation and stale-base guards. Simulate a competing Line revision: a stale draft cannot commit. Discard is explicit; there is no automatic merge. These policies are unaccepted choices from the transaction work, not decisions established by this page.
4. **Editable hidden entry:** choose Hidden tags / recovery. Correct `quieet` strictly inside its plain-text span; untouched italic tokens remain in Raw. Try adding text at the initial tag boundary or replacing across tags: this study refuses to choose boundary affinity or cross-tag ownership. The attempted text appears separately and can be copied into the sample clipboard; Return to Raw retains the source. Drawing and malformed input use Raw-only recovery here. The native study linked below is the substantive mapping experiment.
5. **Spelling and phrase actions:** choose Original with `quieet`, navigate to the issue and apply its authored suggestion. Compare Ignore with Add in memory; both are outside Document undo. An unavailable-dictionary fixture reports unavailable rather than a clean result. Select text and inspect memory copy/cut/paste/delete, local Find next and the dictionary/web/synonym entry. No query is submitted. The explicit quote-conversion button demonstrates one paired-quote transformation only.
6. **Composition and protection:** the Composition guard setup prevents commit/advance. Disable the simulation and Enter should advance. Actual browser composition events also reserve Enter and keep provisional text separate until composition ends, but this is not OS IME qualification. The Protected setup permits selection/copy and refuses mutations. The reference tray's own Next changes only its reference passage.

F6/Shift+F6 traverse Video, Audio, Editor and Grid from current focus. Standard Tab reaches fields, controls and completion results. Raw and hidden views are selected without replacing the authoritative fixture string. Each text role retains its own browser range; the active role is explicit so controls do not silently act on Translated merely because translation mode is visible. Local task dialogs capture Document, Line, role, base revision and draft serial and reject stale application. Native focus/accessibility and long-language behavior remain gates.

## Deliberately limited model

- Committed Lines have stable fixture IDs; drafts bind a Document/Line and base revision. Metadata and both text roles share that draft. Enter commits all valid current draft fields as one sample command and advances in fixture Document order. These draft boundaries, history grouping, confirmation and departure alternatives remain proposals except the already accepted Enter outcome.
- Draft undo stores whole fixture snapshots, capped at 60. Committed undo is a separate button and blocks when the affected Line has a retained draft. It does not model native undo coalescing, IME transactions or the production history contract. Custom slots, ignored words and authored words stay separate from that history.
- The browser hidden projection scans closed override blocks and basic ASS escapes, but only edits within one plain span. A common-prefix/suffix difference identifies the changed interval inside that restricted span; source substrings are preserved around it. Edits at hidden boundaries, across spans, through escapes or within drawing/malformed source are refused. This is deliberately narrower than the native source-map study, and it does not choose before/after affinity or retained-token/cross-tag policy.
- Browser composition is observed for the Enter guard and transient text separation; no platform candidate-window session has been qualified. Provisional text is not copied into the authoritative model until composition ends. Browser event ordering, cancellation, surrounding replacements, focus changes and direct-script inputs need native verification rather than inference from this page.
- Numeric fields use safe JavaScript integers for these tiny fixtures, not a signed-64-bit implementation. Illustrative CPS counts non-space code points, not verified grapheme/reading-speed rules; “rows” counts hard breaks rather than actual native wraps. ASS parameter defaults, BGR/alpha insertion and requested font labels are authored strings, not renderer agreement.

## Root browser observations

On 2026-09-27, browser review found and then rechecked a selection-retention defect: focusing the guided text field had replaced the saved range with an end caret. The corrected setup retains `quieet`; Bold wraps that range and Undo restores the source. Unfocused text-field selection events no longer change the active role.

The Ask-departure flow retained the draft on Stay, then Commit & go changed only A1's actor to Narrator and advanced to A2. In Hidden mode, correcting `quieet` to `quiet` retained the exact italic tags. A leading `X` at the hidden-tag boundary was refused, its attempted text remained available, and Raw recovery retained the valid `quiet` source. Simulated composition held Enter without advancing; disabling that simulation allowed Enter to commit/advance without clearing Unconfirmed. Protected-reference Commit was disabled. These are bounded HTML interaction observations, not real OS composition, renderer or native accessibility evidence.

The initial desktop screenshot also exposed excessive Video height caused by fitting every Editor section vertically. Bounding the upper workspace then exposed overlapping text and metadata in A's constrained grid tracks. A now uses normal block flow inside its local scroll area, so text, metadata and tags retain their content heights; B retains its separate scrolling grid columns. Refreshed desktop inspection confirmed separated text/metadata/tag sections, working section jumps, the bounded Video/Audio/Editor area and Grid directly below; B retained its independent local inspector. Both alternatives were captured. This visual check is separate from native qualification.

Review A/B or a combination for metadata and tag discoverability, retained text space, explicit active role and pending status, and spelling/completion entry placement. The feature ledger identifies depth still required; accepting a local organization would not approve those omitted semantics or the unresolved draft/mapping policies.
