## Official Qt path and authorization boundary

Qt's current CLI documentation explicitly requires account login, through its cache or supplied credentials/token. It documents `QT_INSTALLER_JWT_TOKEN`, `--accept-licenses` and the separate open-source `--accept-obligations`; these options accept terms, rather than merely suppressing progress prompts. `--confirm-command` confirms the mutation. The actual user's account, selected terms, login/cache behavior and expiry are **unverified**. No paid entitlement is assumed. A human must provide the authorized account/license prerequisite outside source/logs before unattended provisioning can be exercised. [Qt CLI](https://doc.qt.io/qt-6/get-and-install-qt-cli.html).

The open-source download page requires a Qt account and verified email. Avoid blanket `--default-answer`: documented defaults include telemetry/file associations enabled and some errors ignored. Use explicit responses and fail on installation errors; select actual package IDs rather than the `sdk` alias that adds latest Qt Creator. [Open-source installer page](https://www.qt.io/development/download-qt-installer-oss), [CLI options and defaults](https://doc.qt.io/qt-6/get-and-install-qt-cli.html).

Public repository listings contain exact base package IDs `qt.qt6.6112.win64_msvc2022_64` and `qt.qt6.6112.linux_gcc_64`. Their archive groups include qtbase, qtdeclarative and qttools, suitable candidates for the required Core/Gui/QML/Quick/Linguist slice. This demonstrates published metadata, not authenticated installer resolution or a complete package closure. [Windows listing](https://download.qt.io/online/qtsdkrepository/windows_x86/desktop/qt6_6112/qt6_6112_msvc2022_64/qt.qt6.6112.win64_msvc2022_64/), [Linux listing](https://download.qt.io/online/qtsdkrepository/linux_x64/desktop/qt6_6112/qt6_6112/qt.qt6.6112.linux_gcc_64/).

## vcpkg and private FFMS2 fit

Rechecked official vcpkg at `ee6a47dac031930715bea2e6dfb9ad60caaa5d83`: `ports/ffms2` returns 404; libass is 0.17.5 and FFmpeg is 9.0.2. The latter is not evidence that the existing FFMS2 fork supports FFmpeg 9. An owned overlay must pin a compatible FFmpeg graph or explicitly qualify necessary fork changes. Do not silently replace the fork with a distro library. [Registry](https://github.com/microsoft/vcpkg/tree/ee6a47dac031930715bea2e6dfb9ad60caaa5d83/ports), [libass manifest](https://github.com/microsoft/vcpkg/blob/ee6a47dac031930715bea2e6dfb9ad60caaa5d83/ports/libass/vcpkg.json), [FFmpeg manifest](https://github.com/microsoft/vcpkg/blob/ee6a47dac031930715bea2e6dfb9ad60caaa5d83/ports/ffmpeg/vcpkg.json).

The local FFMS2 checkout is `45d5f72100d88c52acdd54bfedcc0315a44c735d`. Its core build uses Autotools; the only located CMake files belong to bundled test dependencies. `indexing_additional.cpp` remains in HikariSub baseline `20d647c4c769ab7f5d383cf3c1c33f03876a94e9`, Git blob `be378044fff07bac704f04dc57caa4fc5f95691e`. It includes the fork's private indexing header and defines both members and extra public API. Build it and the core library in one pinned recipe, preserving or deliberately patching its relative includes. The old Linux recipe links distro FFMS2 against that private-header implementation; it is not an acceptable proof slice. [Fork build](https://github.com/altqx/ffms2/blob/45d5f72100d88c52acdd54bfedcc0315a44c735d/Makefile.am), [extra implementation](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/Thirdparty/Build/FFMS2/indexing_additional.cpp), [patch ledger](https://github.com/altqx/hikari/blob/20d647c4c769ab7f5d383cf3c1c33f03876a94e9/Thirdparty/PATCHES.md).

An overlay CMake recipe is the smallest cross-platform candidate, not an already working upstream CMake build. vcpkg permits overlays to add missing ports. Its CMake toolchain normally bootstraps a missing executable, so the pre-`project()` include must supply/verify it first and prove no fallback bootstrap occurred. [Overlays](https://learn.microsoft.com/en-us/vcpkg/concepts/overlay-ports), [CMake integration](https://learn.microsoft.com/en-us/vcpkg/users/buildsystems/cmake-integration).

The sampled recipes add host tooling: libass uses Meson, pkg-config and NASM on x64; FFmpeg acquires MSYS/Automake on Windows and uses Bash plus NASM/pkg-config. These are dependency-owned upstream tools allowed by the contract, but their versions/downloads/cache cost must be captured. They are not permission to add a project bootstrap script. [libass recipe](https://github.com/microsoft/vcpkg/blob/ee6a47dac031930715bea2e6dfb9ad60caaa5d83/ports/libass/portfile.cmake), [FFmpeg recipe](https://github.com/microsoft/vcpkg/blob/ee6a47dac031930715bea2e6dfb9ad60caaa5d83/ports/ffmpeg/portfile.cmake).

## Smallest proposed proof, after prerequisites are resolved

1. **Lock-only preflight:** commit candidate artifact/recipe identities and one CMake provisioning include before the first `project()`. Validate declared compiler/SDK/CMake/Ninja/Git and fail on absent credentials/authorization without exposing secrets. Preserve the official installer owner; first prove how its actual resolved archives can be checked against the committed lock. If that cannot be enforced, report the exact failure and reopen the build decision—do not directly extract Qt archives or substitute aqt/vcpkg Qt.
2. **One Windows Release slice:** one C++ executable and one tiny QML scene, showing runtime Qt/FFMS2/libass versions, rendering an ASS fixture with an original synthetic font, and indexing/decoding a tiny licensed media fixture through the complete fork. Exercise one metadata/attachment extension on valid input; a public version call alone does not prove the private implementation. Compile a tiny translation with Linguist and load it. No application modules, Qt Creator, WebEngine, unrelated add-ons or optional VSFilter.
3. **Reconstruction and deployment:** run `cmake --workflow --preset windows-x64-release` in a named disposable empty-cache directory, repeat configure, then run a new build directory against warm caches. Stage a runnable bundle and launch with SDK/developer library paths removed. Record resolved packages, compiler probes and runtime library origins. Use only disposable copies for missing/corrupt installer/archive/toolchain cases; preserve user installations/caches.
4. **Independent Linux evidence:** repeat on explicitly named Ubuntu/Fedora environments, recording compilers, glibc, host packages and platform-plugin deployment. A Windows pass, WSL build or offscreen smoke alone cannot label both native desktop targets qualified. Add debug and required Windows 10 evidence afterward; report each gate separately.
